## 实际实现

- Java 原子写任务/attempt/outbox、请求幂等、当前状态查询、失败显式重试；不可变素材/模板快照跨重试复用。
- 数据库租约轮询、心跳、退避、交付次数上限及失败回收；旧租约/旧 attempt 和冲突回执不能覆盖当前结果。
- Java 私有本机对象存储，受控素材读取/输出/下载；真实内容、尺寸、摘要和预算校验，硬链接发布避免覆盖已存在产物。
- Python 独立 Worker、本地原子回执 journal、进程锁和重启重放。默认 processor 明确失败；显式合成 fixture 只验证运输。
- 本机开发 bearer 鉴权，用户与 Worker token 分离，无默认凭据、无自动种子。无生产认证或供应商选择。

聚合检查的原生命令包括 npm run check、Maven verify、uv lock --check、Ruff check/format --check 和 pytest。数据库检查会实际启动 PostgreSQL、Java jar 和 Python Worker，不是 mock 回执；子进程由脚本清理。

故障覆盖：四请求并发同幂等键、同 key 不同载荷、outbox 写入注入失败全事务回滚、两个 Worker 并发认领、心跳、过期退避重领、旧租约写入拒绝、摘要错误和重复/冲突回执、并发重试只增一次 attempt、默认 processor 失败、三个独立入口运输、Java 重启、Worker 在领取后/写产物后/落 journal 后/服务端确认后四处退出 91 并恢复、交付耗尽后显式重试、旧 attempt 回执隔离及缺失文件不能成功。

开发过程中发现并修复：urllib 未指定二进制 Content-Type 导致 Servlet 表单过滤消费 PUT body；并发 retry 的联表行锁读取旧 attempt（改为先锁任务、再新语句读取）；uv --project 不切换 cwd（测试启动改 --directory）。前两轮集成失败如实保留在忽略日志，没有计为通过。对象存储先执行两项失败测试后实现，后续通过。独立只读核验后补充了 journal 文件名租约摘要化、损坏记录保留并停止的检查。
