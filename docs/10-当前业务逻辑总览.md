# 当前业务逻辑总览

按 2026-10-09 的代码逐项核对整理，给产品负责人看：系统现在实际怎么工作。决策来源见 [04](04-待决策事项.md)，接口细节见 [02](02-接口与数据契约.md)，进度见 [08](08-当前状态与剩余任务.md)。代码改了而本文没改时，以代码为准，并请同步更新本文。

## 1. 一句话概括

母婴电商图片工作台：用户上传商品图（和赠品图），选择一个入口，把图片作为**参考图**交给 AI 出图模型生成整张主图；营销文字由**程序按原文叠加**，不让模型画字；结果一律**待人工审核**，只提供预览、对照原图和下载，**不自动上架**。

## 2. 系统由谁负责什么

| 部分 | 负责 |
| --- | --- |
| 网页（Vue） | 所有页面与操作；只调用 Java 接口 |
| 业务服务（Java） | 账号、权限、素材、任务、排队、重试、模型配置、审计日志；唯一能读写数据库的部分 |
| 图片服务（Python Worker） | 领取任务、调用 AI 模型、裁切到尺寸、贴赠品方框、叠加文字、上传结果；不连数据库 |
| 数据库（PostgreSQL） | 业务数据；图片文件存在服务器的私有目录 |

一张图的生成路径：网页提交 → Java 检查并“冻结”任务参数 → 排队 → Worker 领取 → 调模型 → 程序加工 → Java 校验结果 → 页面显示。

## 3. 账号、项目与权限

- **登录**：账号密码登录，登录状态保持 8 小时（刷新页面不掉线）；密码 6–15 位；登录过于频繁会被限流；每个账号最多同时 20 个登录会话。
- **角色**：管理员 / 普通用户。管理员可以建账号、停用、删除账号（含该账号的图片）、维护模型配置、模板、公共智能体，查看图片管理、数据看板和操作日志。系统至少保留一个可用管理员；不能删除自己；账号有任务在排队或生成中时不能删除。
- **项目**：每个用户自动有一个默认项目，素材和任务都归属项目；只能看到和使用自己项目里的东西，别人的任务、图片、对话一律返回“不存在”。

## 4. 素材

- **上传**：商品图、赠品图分别上传。系统按文件实际内容判断格式（不看扩展名），上限 50MB、1 亿像素；页面会把浏览器能读但服务器不收的格式转成 PNG。手机照片的旋转方向、CMYK 颜色等在出图时自动转正、转换。
- **素材库**：可以从已上传的原图里选，也可以把“我的作品”（已生成的图）复制成新原图再用（例如在生成好的图上加卖点文字）。
- **删除**：本人可删除自己的原图和作品；管理员可在“图片管理”删除任何人的。正在排队或生成中的任务用到的原图不能删。删除后所有入口都看不到；历史任务保留占位，引用了已删原图的失败任务不能再重试。

## 4b. 各类图片的对应关系

| 名称 | 存在哪里 | 在哪里用 | 发给模型时的用途 |
| --- | --- | --- | --- |
| 商品图 | 素材 → 商品图 | 四个入口都必选 | 要卖的商品，外形、颜色、Logo、文字不变；“保持原图”时直接作为底图 |
| 赠品图 | 素材 → 赠品图 | 赠品主图 | 作为第二张参考图让模型画进画面，或放进程序画的方框（纯白时先由模型重拍白底） |
| 参考图1 / 参考图2 | 素材 → 赠品图（对话生图的参考图位置用的是赠品图库） | 只在对话生图 | 用途由你的描述决定：底图、要加入的物品或只学样式 |
| 作品 | 我的作品（生成结果） | 对话生图“继续修改”时作为“要修改的图”；也可复制成新的商品图或赠品图 | 修改时作为第 1 张图 |

“素材”就是上传的原图，只有商品图、赠品图两种；“参考图”不是单独的存储类型，而是图片在一次生成里的用途。

## 5. 四个生成入口

### 5.1 共同规则

- **尺寸**：800×800、750×1000、1000×750、720×1280、1280×720、800×1200、1200×800（技术预设，**不是**拼多多规则，平台规则未核实）。格式 PNG。
- **张数**：赠品、场景、对话每次 1–4 张；卖点图张数 = 卖点条数（1–6）。
- **清晰度**（2026-10-09 起）：
  - 尺寸：标准 = 上面的尺寸；高清 = 同比例约 2 倍（如 1600×1600，长边不超过 2048），模型按 2K 出图。只有能按 2K 出图的模型（Seedream、Nano Banana 2/Pro/2.1）可选；`gpt-image-2` 只能选标准。“保持原图”不调用模型时也可选高清，直接放大原图。
  - 画质：标准 = 管理员给模型设的参数；高清 = GPT Image 画质“高”，Seedream / Nano Banana 用 2K。不调用模型时没有这一项。
  - 两者都会增加费用；所选模型不支持时按钮置灰。
- **模型**：从管理员配置的“出图模型”里选，默认用管理员设的默认模型。任务提交时就记下用哪个模型，之后改配置不影响已提交的任务。
- **保护条款**：凡调用模型，提示词都要求：商品（和赠品）的外形、比例、颜色、材质、Logo、包装文字、数量不变；不在图中新增任何文字、水印、标签。模型仍可能细微改动，所以结果页提供“对照原图”，结果一律待人工审核。
- **程序加工**：模型输出的图按所选尺寸居中裁切（固定算法，可复查），再贴方框、叠文字。

### 5.2 赠品主图

输入：商品图 + 赠品图。可选：

- **赠品位置**：右下（默认）/ 左下 / 右侧 / 左侧。
- **背景**：纯色（纯白、奶油、柔粉、天蓝、薄荷、燕麦）/ 描述（自己写背景）/ 保持原图。
- **赠品方框**（可选）：白色圆角卡片 + 顶部绿色“+”，大小 小/中/大，可写方框文字（≤10 字，显示在赠品下方）；方框底色：原图背景 / 纯白。
- 赠品主图**不带营销文字**；需要文字时，把生成好的图在卖点主图里用“保持原图”加字。

| 组合 | 模型怎么做 | 每个任务的模型调用 |
| --- | --- | --- |
| 不加方框，纯色或描述背景 | 商品图、赠品图都发给模型，生成整张图，赠品在所选位置 | 每张 1 次 |
| 不加方框，保持原图 | 模型在原图空白处加入赠品，要求原图所有人物、物品、文字不动（模型重画整张，原图可能被改动，页面有提示） | 每张 1 次 |
| 加方框，纯色或描述背景 | 只发商品图，要求模型把方框位置留空；程序把方框贴上 | 每张 1 次（底色纯白再加 1 次） |
| 加方框，保持原图，方框底色“原图背景” | 不调用模型：商品原图居中裁切后直接贴方框，原图完全不变 | 0 次 |
| 加方框，保持原图，方框底色“纯白” | 原图不变；只让模型把赠品单独重拍成白底 | 1 次 |

方框里的赠品：

- **原图背景**：赠品照片原样放进方框（带它自己的背景）。
- **纯白**（2026-10-09 起）：把赠品照片单独发给模型，重拍成纯白背景、带自然浅阴影的商品照（去掉原背景和背景上的文字杂物，赠品本身不变）。程序再把背景校正为纯白、裁到赠品、放大放进方框、边缘渐隐，不画描边。同一任务的几张图共用这一次重拍。模型返回的背景不够白时，整张原样放入。

### 5.3 场景主图

- 输入：商品图。场景：6 个预设（婴儿房、木质桌面、浴室台面、户外草地、厨房台面、卧室床品，可由管理员修改）或自定义描述，预设也可以加补充描述。
- 模型把商品自然地放进该场景。每张 1 次调用。无文字叠加。

### 5.4 卖点主图

- 输入：商品图；标题（≤60 字，可换行）；卖点 1–6 条（每条 ≤20 字）；文字颜色；文字框位置（预设位置或在画布上拖动、缩放）。
- **每条卖点一张图**：第 i 张写“标题 + 第 i 条卖点”。
- **风格**：
  - AI 风格（4 个预设：暖木奶油、柔和粉、自然绿、清新蓝，可由管理员修改）：模型按风格生成画面，并用场景、道具、构图表现第 i 条卖点（不画字），要求空出文字区。商品位置可选 自动 / 左侧 / 居中 / 右侧（自动 = 放在文字框另一侧；所选位置与文字框重叠太多时页面会提示）。每条卖点 1 次调用。
  - 保持原图：不调用模型、零费用，直接在商品图（可用已生成的作品）上居中裁切后加字。
- **文字叠加**：程序用配置的字体（测试服务器为方正兰亭圆简体_中粗）按原文绘制标题和卖点标签，放不下时整体等比缩小，标题小于 12px 仍放不下则不生成（页面会在提交前提示，避免花了钱才失败）。
- **应用文字修改**：生成后改字、换颜色、拖动位置，点“应用文字修改”只重新叠字，复用原来的模型图，不再调用模型、不收费。

### 5.5 对话生图

- 输入：商品图（必选）+ 最多 2 张参考图（参考图1、参考图2）+ 自己写的描述（1–1000 字）。
- 生成后可以选任意一张“继续修改”，下一句话就是在这张图上改；也可以取消改为重新生成。
- **图片名称**（2026-10-09 起）：发给模型时按页面上的名称逐张说明（「要修改的图」「商品图」「参考图1」「参考图2」）。描述里直接用这些名称，例如“在参考图1的基础上，把商品图作为赠品加进去，展示方式参考参考图2”。每张图的用途由用户的话决定，不再默认商品一定是主角。以某张图为底（如“在参考图1的基础上”）时，要求模型保留底图全部内容和位置，新增的东西只放空白处；只作“展示方式”参考的图，要求忠实复现它的卡片或边框、颜色、圆标和符号（如“+”），不自己加彩带等装饰。对话生图不让模型画字，所以加的赠品卡片没有文字；需要原图像素级不变、卡片带文字时，用赠品主图的“保持原图 + 赠品方框”。
- **先看图、再出图**（2026-10-09 起，管理员配置了文本模型时默认开启）：每条消息出图前，先把所有图片交给文本模型，让它写清每张图的内容（底图上的人物、文字、标志、角标和空白位置，参考图里卡片的形状、颜色、圆标和“+”等细节，商品外观）和出图方案，再把你的原话加这份说明交给出图模型；对话里显示“看图分析”。每条消息多一次文本调用（约 0.002 美元，多 5–15 秒）；分析失败时不出图、不收出图费用。图片的缩小副本会发给文本模型的服务商。
- **智能体**：可选一个智能体（预置公共的 Gloria / Lumi / Kira，管理员可加公共的，每个人可建自己的）。它的“设定”会和描述一起交给模型；设定与用户原话冲突时以用户为准。
- **魔法棒**（需要管理员配置文本模型）：点亮后，看图分析的同时按智能体设定把描述改写成更专业的出图描述（对话里显示“某某 看图改写”），仍是每条消息 1 次文本调用；改写失败时不会再调用出图模型。
- 保护条款同样追加；对话可删除，删除后图片仍在“我的作品”。

## 6. 一次生成从提交到出图

1. **提交**：页面带一个唯一请求号提交。网络中断后再点一次会用同一个请求号和同样内容重发，系统识别为同一个任务，不会重复生成；内容不同则拒绝。
2. **冻结**：Java 检查参数，把所用原图（按文件哈希）、模板版本、场景/风格内容、智能体设定、模型配置版本全部记进任务。之后管理员改模板或模型，不影响这个任务和它的重试。
3. **排队**：任务进入队列（状态“排队中”）。服务器上 Worker 默认同时处理 2 个任务。
4. **领取**：Worker 领取任务（状态“生成中”），领取有时限，过程中定时续期；Worker 中途掉线，任务会被重新派发，最多 3 次。
5. **调用模型**：每次付费调用前先向 Java 领一张“付费许可”（每张图一张，赠品重拍单独一张）。同一张许可只能用一次，保证掉线重派时不会对同一张图重复付费。
6. **加工**：裁切到尺寸 → 贴赠品方框 → 叠文字 → 上传结果图和模型原图（模型原图留作“应用文字修改”用）。
7. **校验**：Java 核对张数、尺寸、格式、每张图的输入哈希、模型来源记录、裁切参数都对得上，才把结果一次性发布（状态“已完成”）。核对不过则任务失败，不会出现半套结果。
8. **失败与重试**：失败时页面显示具体原因（如“出图模型的 API Key 无效或无权限”“看图分析失败：文本模型不存在或路由标签不匹配”“文字放不下”）。可重试的失败由用户点“重试”，同一任务最多 5 次尝试；每次重试是新的尝试，会重新调用模型并收费。

每次结果都记录：模型、服务商、提示词、参数、输入图哈希、请求关联号、输出来源和耗时（不含密钥），供追溯。

## 7. 模型与费用

- **编辑与删除**（2026-10-09 起）：模型可直接编辑（含密钥、参数），立即生效，已提交还没完成和失败后重试的任务也用新设置；可彻底删除，默认模型要先换掉才能删，被删模型的未完成任务改用默认模型，已完成的图片不受影响。
- **模型参数**：按模型列出可调选项（GPT Image 画质档、Seedream / Nano Banana 分辨率、文本模型创意程度），选项来自系统内置清单（按 OpenRouter 公布的能力整理），生成前还会让 OpenRouter 再核对一次。
- **模型配置**（管理员）：接口类型 OpenRouter、OpenAI 官方、Gemini 官方、OpenAI 格式第三方、Gemini 格式第三方；每个模型有名称、启停、是否走代理、默认；API Key 加密保存，不显示、不进日志。
- **用途**：出图模型 / 文本模型（看图分析与魔法棒）分开配置、分开设默认。OpenRouter 出图接口除 `openai/gpt-image-2` 外还有字节 Seedream 5.0（`bytedance-seed/seedream-5-0-pro`，标签 `seed`，与豆包同系列）、Google Gemini 3 Pro Image 等，管理员添加后即可在生成页选择（2026-10-09 查询，未做真实对比）。OpenRouter 出图模型必须指定服务商路由标签（图片只发给指定服务商）；文本模型的路由标签只是“优先使用”，也可以不填。
- **网络代理**：在页面设置，按模型勾选是否使用。

一次任务的模型调用次数：

| 情况 | 出图调用 | 文本调用 |
| --- | --- | --- |
| 场景主图 | 每张 1 次 | — |
| 对话生图 | 每张 1 次 | 配置了文本模型时每条消息 1 次（看图分析，魔法棒时兼做改写） |
| 赠品主图 | 每张 1 次；加方框且保持原图时 0 次；方框纯白再加 1 次 | — |
| 卖点主图 | AI 风格每条卖点 1 次；保持原图 0 次 | — |
| 应用文字修改 | 0 次 | — |

真实耗时参考：测试服务器上 `gpt-image-2` 每张中位 22–31 秒，最长约 40 秒。

## 8. 模板与智能体

- **管理员模板**：场景预设、卖点风格可编辑，保存即发布新版本，可回退或恢复内置默认；新任务立即使用新版本，已提交的任务沿用提交时的版本。
- **我的模板**：三个生成页可保存、套用、删除个人参数模板（不含图片和文字内容）。
- **智能体**：名称、一句话介绍、设定、头像；公共的由管理员维护，个人的只有本人可见可改。

## 9. 管理与统计

- **图片管理**：管理员按账号查看、删除所有人的原图与作品（规则同本人删除，记审计）。
- **数据看板**：任务数、张数、成功率、耗时、排队情况，每日趋势，按功能、模型、账号分组。
- **操作日志**：按人和动作筛选；目前不自动清理（保存期限待决定）。

## 10. 明确不做的事

- 不自动上架、不发布到拼多多；不硬编码未核实的平台尺寸和审核规则。
- 不让模型画营销文字；商品图不抠图（赠品方框纯白时由模型重拍赠品，也不是程序抠图）。
- 不宣称生成图中的商品与原图一致；结果一律待人工审核。
- 不做批量 SKU、多租户、通用节点编辑器、自动生成卖点。

## 11. 已知限制与待决定

- AI 效果有随机性：保持原图背景（不加方框）时模型重画整张，可能改动原图内容；赠品重拍、卖点画面、对话生图都需要人工核对。2026-10-09 的两项修正（对话图片名称、纯白方框 AI 重拍）尚未做真实出图验证。
- 待用户决定：D-01 拼多多尺寸与文字规则；D-07 一次可生成数量上限（当前 4）；D-13 对话生图是否允许关闭保护条款、允许模型画字；卖点“应用文字修改”时新增的卖点怎么排版；日志保存期限；Worker 同时处理数量（当前 2）。
- 上线前：受信 HTTPS 证书（当前为内部 CA，需在每台电脑安装）。
