# 接口与数据契约：已实现 v1 与待实现演进

第 0 节及第 5–7 节、T06 节记录已实现的开发接口；第 1–3 节为初期草案，冲突时以已实现节及 Schema 为准。第 8 节记录 2026-09-26 用户决定后的目标契约，尚未实现，不得当作现有 API 能力。所有资源 ID 为服务端生成的 opaque string；时间为带时区 ISO 8601；业务数量上限仍待确认。

## 0. T01 开发环境健康接口

需求：PRD-G06；任务：T01；验收：ACC-T01。两个端点只反映当前 HTTP 进程可响应，不承诺数据库、Worker、AI 或业务就绪。

| 调用方 → 服务 | 方法与路径 | HTTP 200 JSON |
| --- | --- | --- |
| 前端 → Java | `GET /api/v1/health` | `{"status":"UP","service":"business-service","api_version":"v1"}` |
| 开发检查 → Python | `GET /internal/v1/health` | `{"status":"UP","service":"image-service","api_version":"v1"}` |

无输入、无密钥、无素材、无业务状态写入。前端通过 Vite 的 `/api` 开发代理访问 Java，不直连 Python。两服务默认仅绑定 `127.0.0.1`，没有实现认证，不能作为生产部署。前端在连接失败、超时或响应不符合上述字段时显示失败并允许重试。后续业务健康/就绪语义须单独定义；本次不改变任务 Schema。

## 1. 前端 → Java（/api/v1）

| 方法与路径 | 用途 | 要点 |
| --- | --- | --- |
| `POST /assets/uploads` | 获取受限上传凭证或走服务端上传 | project_id、type=PRODUCT/GIFT；回收未完成上传 |
| `POST /assets/{id}/complete` | 校验上传完成并处理元数据 | 校验 MIME 真值/文件大小/像素数/哈希/归属；返回可预览状态 |
| `POST /assets/{id}/cutout` | 发起或取得抠图结果 | alpha 预览与人工确认状态 |
| `GET /templates?type=scene|layout|style` | 已发布模板 | 返回版本、预览与允许参数 |
| `POST /tasks` | 创建独立生成任务 | 必须携带 `Idempotency-Key` 和 `feature_type`；返回 202 |
| `GET /tasks/{id}` | 轮询状态与结果 | 只返回当前授权用户可读的信息 |
| `POST /tasks/{id}/retry` | 针对失败任务重试 | 新 attempt，不能改写原配置快照 |
| `GET /artifacts/{id}/download` | 下载已授权结果 | 代理或短时效签名链接 |
| `POST /admin/templates` 等 | 草稿、测试、发布、停用 | 仅管理员；另行定义管理 API 细节 |

示例 `POST /tasks`：

```json
{
  "project_id": "p_123",
  "feature_type": "GIFT",
  "product_asset_id": "a_product",
  "gift_asset_id": "a_gift",
  "manual_text": "下单赠清洁刷",
  "template_version_id": "tv_layout_1",
  "layout": {"product": {"x": 0.12, "y": 0.11, "width": 0.72, "height": 0.72}, "gift": {"x": 0.70, "y": 0.72, "width": 0.22, "height": 0.22}},
  "output_preset_id": "preset_draft_1"
}
```

坐标是相对画布的 0..1 比例，原点左上。D-02 已允许等比例缩放、旋转、裁切，但旋转中心、裁切坐标系及越界语义须在版本化变换契约中统一；v1 不因此新增字段。赠品默认右下是界面初始值，可编辑；`output_preset_id` 在拼多多规格确认前只代表内部预览导出配置。

`SCENE` 专有字段：`scene_template_version_id` 或 `scene_custom_prompt`、可选 `style_custom_prompt`、商品布局；两种场景输入可以有明确组合规则，但不能都为空。`SELLING_POINT` 专有字段：`selling_points`（人工字符串数组）和 `layout_template_version_id`；数量分配及可选上限待 D-07 确认，不规定一条文案必定一张。三种类型使用 discriminated union 校验，绝不根据缺失字段猜类型。

统一任务响应：

```json
{
  "id": "t_123", "feature_type": "GIFT", "status": "QUEUED",
  "attempt": 1, "created_at": "2026-09-24T00:00:00Z",
  "artifacts": [], "error": null
}
```

失败响应示例：`{"code":"CUTOUT_REVIEW_REQUIRED","message":"请检查商品抠图边缘","correlation_id":"..."}`。最小错误码：`INVALID_ASSET`、`UNAUTHORIZED_ASSET`、`CUTOUT_REVIEW_REQUIRED`、`INVALID_LAYOUT`、`TEXT_OVERFLOW`、`PROVIDER_UNAVAILABLE`、`GENERATION_FAILED`、`OUTPUT_VALIDATION_FAILED`、`TASK_CONFLICT`。内部故障细节与供应商错误不得直接暴露。

## 2. Java → Python Worker

Java 在数据库事务中提交任务与 outbox 记录；发布器投递 `image.task.requested.v1`。Worker 只读取受限的对象引用/临时访问令牌，结果写到任务限定路径，回执 `image.task.completed.v1` 或 `image.task.failed.v1`。不得在消息体存放图片二进制、用户密码或长期密钥。初期若采用 DB 轮询，保留同一请求与回执语义。

请求契约草案见 `contracts/task.schema.json`，含 `schema_version`、`task_id`、`attempt_id`、`feature_type`、输入资产引用及哈希、模板快照和参数、目标路径、关联 ID。成功回执包含产物类型、对象引用、sha256、尺寸、耗时、供应商与模型标识；失败回执包含可重试标记、内部错误码和安全消息。Java 在更新状态前核验 attempt_id 与产物存在性，重复回执幂等处理；旧回执只记录不覆盖。

## 3. 表模型（概念级）

| 表 | 主键与关键字段 | 约束 |
| --- | --- | --- |
| `users` | id、role、status | 最小权限 |
| `projects` | id、owner_id、name | 项目归属 |
| `assets` | id、project_id、kind、object_key、sha256、width、height、review_status | 类型与访问权校验；源图不可被替换 |
| `templates` | id、type、name、published_version_id、state | 模板身份稳定 |
| `template_versions` | id、template_id、version、config_json、created_by、published_at | 一旦发布不可改写 |
| `generation_tasks` | id、project_id、feature_type、status、request_snapshot_json、created_by、created_at | type/状态受限；配置快照 |
| `task_attempts` | id、task_id、attempt_no、status、started_at、ended_at、error_code、provider_info | 唯一(task_id, attempt_no) |
| `artifacts` | id、task_id、attempt_id、kind、object_key、sha256、width、height | 成品不可悄然覆盖 |
| `outbox_events` | id、event_type、payload、published_at | 可恢复发布 |
| `audit_events` | id、actor_id、action、resource_id、timestamp | 记录敏感变更 |

用数据库迁移脚本实现；object_key 不应是公网永久地址。D-08 已决定图片默认永久保存、生产者及管理员可删除且无备份恢复；孤立对象处理、删除传播与日志期限尚待落实，现有程序不因此自动删除。

## 4. 版本策略

对外 API `/api/v1`；任务 schema 有独立 `schema_version=1`；模板发布产生不可变版本；Prompt、供应商/模型和原图/alpha 哈希存任务快照。破坏性更改先引入新版本并让前端/Worker 双方通过契约测试，然后滚动发布。建议从契约生成 Java/Python/TypeScript 类型，但生成器是实现选项，不能取代人工审核语义。

### 5.1 规范源与兼容性

`contracts/*.schema.json` 是 Draft 2020-12 规范源；`common.schema.json` 共用结构；前端、Java、Python 使用同一批 `contracts/fixtures/cases.json` 正反样本验收。所有引用仅解析仓库/JAR 内注册的 schema，不按用户输入下载 schema。`https://schemas.product-image-workbench.invalid/v1/` 是离线标识，不是网络服务。

| 文件 | 协议 |
| --- | --- |
| `task-create.schema.json` | `POST /api/v1/tasks` 请求体，按 feature_type 区分三种独立输入 |
| `idempotency-key.schema.json` | 请求头 Idempotency-Key 的语法；可见标识字符 1..128，属于技术协议限制，不是业务配额 |
| `task-response.schema.json` | 对外任务响应；不暴露对象存储 key 或供应商内部错误 |
| `task.schema.json` | `image.task.requested.v1`，保留原草案文件路径 |
| `task-completed.schema.json` | `image.task.completed.v1` |
| `task-failed.schema.json` | `image.task.failed.v1` |

原 `task.schema.json` 是未被运行代码使用的草案。此次首次固化 v1，增加事件标识、必需的 alpha/快照、严格分支及回执，没有既有业务数据或已发布协议需要迁移。后续破坏性修改必须新增 v2，不得静默修改 v1 的语义。生产数据库一旦应用迁移，不得修改已应用 SQL，应新增 V2、V3。

### 5.2 输入和回执规则

- GIFT 必须有独立 gift 输入及布局，SELLING_POINT 必须有至少一条非空人工卖点，SCENE 至少有场景模板或自定义描述。其他功能的专有字段拒绝；所有固定结构拒绝未知字段，不自动类型转换、不补写默认业务值。
- 输入引用使用非空 opaque ID；对象 key 为不含 URL、反斜杠、查询串、路径回退段的内部 ASCII 相对 key。哈希统一小写 64 位 SHA-256；图片二进制、永久 URL 和密钥不属于任务字段。
- v1 布局只定义 x/y 为 0..1、width/height 为正有限数。D-02 已批准等比例缩放、旋转、裁切，但其版本化字段与渲染语义尚未实现；v1 语法通过不代表这些图像能力已可用。
- Worker 请求必须有原商品及 alpha 引用、模板/输出预设快照、输出前缀、event_id/task_id/attempt_id/correlation_id。赠品有独立引用，卖点仅传人工原文。快照中的 config 是版本化模板的透明配置载荷，此时不定义模板渲染语法，也不能直接当 AI 请求。
- 每个模板版本快照包含发布人、发布时间、版本及配置；自定义场景允许 versions 为空，输出预设仍需快照。场景模板描述与自定义描述可同时原样携带，本任务不执行拼接或生成。最终组合逻辑在 T09/模板规范中处理。
- 成功回执携带非空产物清单、ordinal、对象 key/哈希/尺寸、耗时，以及可空的 background_generation。使用 AI 背景时，该元数据必须含供应商、模型、提示词、生成参数、请求关联 ID、输出来源；这不是供应商选择。纯确定性产物填 null。
- 失败回执携带安全错误码、安全消息、retryable 和耗时。回执始终关联明确 attempt；对外 FAILED 响应只暴露安全错误，不公开供应商元数据。
- 日期时间必须带时区且为有效 date-time。QUEUED/RUNNING 响应无产物且 error=null；SUCCEEDED 至少一张产物且无错误；FAILED 无成功产物且有错误。实际状态推进、产物存在性校验、回执去重执行和旧 attempt 处理属于 T05。

### 5.3 数据库基线及幂等约束

PostgreSQL 是唯一业务数据库；由 Java 的 Flyway 管理迁移。Python 不装 PostgreSQL 驱动、不连接业务数据库。

V1 建立 users、projects、assets、templates、template_versions、generation_tasks、task_attempts、artifacts、outbox_events、worker_receipts、audit_events。ID 为 text，时间为 timestamptz，JSON 配置/快照为 jsonb。仅建立结构，不创建真实用户、管理员、素材、模板或供应商；users.role 不预设权限体系，等待 D-05/T04。

- 任务唯一键为 `(created_by, feature_type, idempotency_key)`，同时保存 `request_sha256` 与原始请求快照。相同用户/功能/key 无法插入第二个任务，即使哈希不同；不同用户或功能不互相占用 key。
- 幂等 SHA-256 由 Java 唯一计算：对象键排序、数字去除无意义尾零、数组顺序及字符串原文保留、UTF-8。拒绝重复 JSON 键、尾随 JSON 和不成对的 Unicode 代理字符，避免 UTF-8 替换产生指纹歧义。`1` 与 `1.0` 等价，不把不同文案或不同数组顺序当成相同输入。Python/浏览器不得另算一个不兼容的指纹。
- T03 验证唯一约束及并发冲突。相同 key/相同哈希返回既有任务、不同哈希返回 TASK_CONFLICT 的 HTTP 行为待 T05 在事务服务中实现，不能把唯一键异常直接当作成功。
- attempt 唯一 `(task_id, attempt_no)`；当前 attempt、产物、outbox 和回执通过复合外键绑定同一 task/attempt；产物唯一 `(attempt_id, ordinal)`，防止重试重复登记可见槽位。
- outbox 对同一 attempt 的请求事件唯一；worker_receipts 的 event_id 和 attempt_id 唯一，保存回执哈希供 T05 检查“重复事件却不同载荷”。这些表当前没有发布器/消费者。
- 任务商品引用必须指向 PRODUCT，赠品引用必须指向 GIFT；alpha 只能派生于原始 PRODUCT/GIFT，不能套用另一份 alpha。模板的发布指针必须指向已发布版本，PUBLISHED 状态必须有该指针；停用可保留历史发布版本。
- 源资产身份/来源、任务请求快照、已发布模板版本及产物记录不可覆盖；版本发布后不可更新或删除。更改产物应创建新 attempt/产物，保留旧记录。正式删除策略仍待 D-08，不实现自动删除。
- CHECK 校验状态、类型、正整数尺寸/序号、哈希、JSON 基本结构；复合外键防止任务引用另一项目资产、或引用另一个任务的 attempt。相应 FK 和轮询预期列建立索引，不引入 RLS/SSO 策略。

数据库能力仅在 `database` profile 显式启用，连接通过 DB_URL/DB_USER/DB_PASSWORD 注入；缺少配置必须启动失败。默认健康服务继续无数据库启动。无真实密钥的隔离验证使用 `scripts/check_db.py` 创建临时集群与一次性口令，日志和数据均在忽略目录。迁移默认禁用 clean/baseline-on-migrate；升级校验错误必须明确失败，不自动重建业务库。

## 6. T05：可恢复任务运行时（本机开发边界）

任务 T05 / PRD-G03/G06 / ACC-07/08/10。沿用 v1 任务载荷，不修改 V1 迁移；V2 增加 outbox 租约、投递次数/下一次可用时间、任务输出预设及回执租约标识。Java 是业务数据库唯一访问方。采用持久化 outbox + Java HTTP 认领的数据库轮询，不依赖额外消息中间件；这不是同步等待 Python 生成的请求链路。

### 6.1 开发访问与任务入口

显式 `runtime` profile 包含 `database`，只允许本机绑定。配置两枚互不相同的至少 32 字符随机令牌：用户 API Bearer 令牌映射到已有 `RUNTIME_USER_ID`，Worker Bearer 令牌仅用于内部端点。无默认令牌、无启动种子、无公开文件目录。用户必须 ACTIVE 且为项目 owner；这是 D-05 未决时的可替换本机开发认证，不是正式 SSO/项目成员策略。

- `POST /api/v1/tasks`：v1 请求 + Idempotency-Key；202 返回任务。授权后按原始请求规范化指纹；相同用户/功能/key 与相同内容返回原任务，内容不同 409 TASK_CONFLICT。任务、attempt、不可变请求/模板/原图/alpha 快照与 outbox 同事务提交。商品 alpha 必须已 APPROVED；引用的模板必须已发布且未停用。输出预设从受控数据库配置读取，不从请求任意指定尺寸规则。
- `GET /api/v1/tasks/{id}`：v1 状态，仅返回当前 attempt 的已登记产物；无权读返回 404。
- `POST /api/v1/tasks/{id}/retry`：请求体 `{ "attempt": 正整数 }` 绑定失败的期望 attempt。仅 retryable 的 FAILED 可重试；并发或重复重试不会再创建额外 attempt。已从该 attempt 重试时返回当前任务；过期不匹配请求 409。保留原请求与素材/模板快照，新 attempt 使用独立输出目录。
- `GET /api/v1/artifacts/{id}/content`：开发用鉴权字节代理；不暴露文件路径/永久 URL。正式下载体验属于 T10。

### 6.2 Worker 传输与恢复

- `POST /internal/v1/work/claim`：无输入；无任务返回 204，有任务返回 `{lease_token, lease_seconds, request}`，request 为原 v1 Worker 请求。数据库行锁 SKIP LOCKED 保证并发认领互斥；认领和 RUNNING 状态同事务提交。Worker 不直接查询 PostgreSQL。
- `POST /internal/v1/work/{attempt}/heartbeat`、`GET /internal/v1/work/{attempt}/assets/{asset}`、`PUT /internal/v1/work/{attempt}/outputs/{ordinal}`、`POST /internal/v1/work/{attempt}/receipt` 均要求 Worker Bearer 及 X-Lease-Token。读取仅限该快照素材；写入由 Java 派生该 attempt/lease/ordinal 的对象 key，不能上传自选路径。PUT 返回对象 key、sha256 和真实图片尺寸，Worker 用于 completed v1 产物字段。
- 租约过期任务可再次认领，同一 attempt 的不同租约写入不同目录，旧 Worker 不能覆盖新产物。投递有可配置上限及退避；达到上限转 FAILED/GENERATION_FAILED/retryable=true，不永久卡在 RUNNING。定时 Java 扫描和认领时均回收超时；显式重试产生新 attempt。
- Worker 采用独立进程，回执先落本地原子 journal，再发送；网络失败重试同一回执/event_id，进程重启继续发送。回执仅确认后删除 journal；过期租约回执被明确 IGNORED 并审计，不改变当前任务。
- Java 在任务锁内验证回执 schema、事件/关联/attempt/租约、产物存在、哈希、真实尺寸、独立 ordinal 和限定输出前缀；所有产物登记、回执去重、终态与 outbox 完成同事务提交。重复同 event/同内容不重复登记；不同内容或冲突终态回执 409。安全错误码映射为固定对外消息，不透传供应商异常或 Worker 自带错误文本。

### 6.3 存储及未实现图像功能

本机文件对象存储只有 Java 访问，根目录显式配置；拒绝路径回退/符号链接，限制输入字节/像素预算，按内容识别 PNG/JPEG。暂存写入完成并刷盘后用同文件系统硬链接发布，目标存在时只接受完全相同字节；不支持硬链接的文件系统明确失败，不采用可能覆盖目标的 ATOMIC_MOVE。下载和回执验证均重新核对内容。数据库失败后的孤立对象保留，待 D-08 清理规则，不自动删除。

默认 Python processor 返回明确的未配置失败；T02/T07/T08/T09 不在 T05 中伪实现。显式 fixture processor 仅接受输出预设 `t05_transport_fixture`、`fixtures/` 合成素材，复制预先给定的合成 PNG 来验证存储/消息/状态，不生成可交付商品图，不调用 AI。该适配器只用于隔离验收。

租约、投递上限、退避、文件/像素预算是可配置开发保护值；JSON 请求体技术上限为 262144 字节。这些不是平台规格或业务额度。生产本地账号、真实 pipeline、OpenRouter 接入与人工审图仍按 T04/T02/T07..T11 推进；对象存储部署待验证。D-08 已取消备份恢复要求，不取消本节的任务恢复。

T05 运行约定补充：内部输出 PUT 必须使用 `Content-Type: application/octet-stream`，避免 Servlet 表单解析消费二进制请求。场景模板版本的 `config_json.prompt` 保存已审核提示词，Java 仅原样快照，不决定供应商或用户描述拼接规则。Worker 的 REJECTED 确认表示 Java 已原子保存拒绝回执并将任务置为失败，可清理本地 journal；协议错误的 HTTP 409 不属于该确认。损坏 journal 保留现场并停止 Worker，由运维检查后恢复。

## 7. T04 可先行：开发本地认证、项目与原图上传

D-05 已选生产本地账号；本节仍只定义已实现的开发适配器，不能作为生产认证或最终项目成员权限。`UserAuthenticator` 从请求 Bearer 返回当前用户 ID；业务服务显式接收该 ID，不再固定使用进程配置用户。T05 runtime 静态 bearer 保留兼容；新 `dev-local` profile 包含 runtime，仅在 `APP_ENV=development` 且仅启用 dev-local/runtime/database、绑定回环地址时可启动。本地账号仅从显式私有文件 DEV_ACCOUNTS_FILE 加载（无默认账号/公开注册），密码为 PBKDF2-HMAC-SHA256、600000 次、独立 16 字节 salt、32 字节摘要；启动只创建配置中的缺失开发用户，不重启已禁用用户。Worker token 始终独立，dev-local 不接受旧 RUNTIME_API_TOKEN。

- `POST /api/v1/auth/login`：严格 JSON `{username,password}`；成功 200 `{access_token,token_type:"Bearer",expires_at,user:{id},mode:"development-only"}`，no-store。失败统一 401，不泄露账号存在性；登录每进程技术保护上限 30 次/分钟。会话随机 256 位，内存仅存摘要，默认 900 秒（DEV_SESSION_SECONDS 2..3600），最多 256 活跃会话；重启失效。仅显式 Authorization，不用 cookie/query token。`GET /api/v1/auth/me` 返回 `{id,mode}`；`POST /api/v1/auth/logout` 撤销当前会话并返回 204。登录端点仅 dev-local 存在。
- `POST /api/v1/projects`：严格 `{name}`，去首尾空白后 1..120 字符，201 返回 `{id,name}`；owner 来自认证身份，不能提交 owner/role。`GET /api/v1/projects` 返回自身项目列表（最多最近 100 项）；`GET /api/v1/projects/{id}` 返回自身项目。当前开发策略仅 ACTIVE 用户访问自己项目，不授予管理员跨项目权限；非本人或不存在一律 404。
- `POST /api/v1/projects/{id}/assets?kind=PRODUCT|GIFT`：单阶段服务端上传，原始请求体，Content-Type 必须为 image/png 或 image/jpeg 且匹配实际内容；返回 201 `{id,project_id,kind,sha256,width,height,review_status:"PENDING",content_url}`。这取代第 1 节未实现的 uploads/complete 两阶段草案，本阶段不发外部上传凭证。只允许原始 PRODUCT/GIFT，拒绝 ALPHA/派生来源/客户端存储路径；不凭文件名或声明信任内容。
- （ADR-20260930-D 起本条取代为：以文件内容判断 PNG/JPEG，忽略声明的 Content-Type；保留全部元数据；只读文件头取尺寸；PNG 需以 IEND 结尾且其后无数据，JPEG 需有帧头、扫描数据与结束标记，结束标记后的附加数据保留；未知格式 415、不完整 422、超过 `OBJECT_MAX_BYTES`（默认 50MB）/`OBJECT_MAX_PIXELS`（默认 1 亿）或单边 65535 为 413；其他格式由页面转 PNG 后上传。以下为历史规则。）上传先认证/检查项目，再有界读取（沿用 OBJECT_MAX_BYTES/OBJECT_MAX_PIXELS，单边最大 16384），检查实际完整 PNG/JPEG、损坏/截断/尾随数据与元数据。开发允许的 PNG chunk 为 IHDR/PLTE/IDAT/IEND/tRNS/sRGB/gAMA/cHRM/pHYs；拒绝文本、压缩 ICC、EXIF、动画及未知 chunk。JPEG 只接受基线/渐进的常规解码输入，拒绝 APP1..APP15、COM 等未支持元数据，保留 APP0/JFIF。这是可收紧的开发输入限制，不是平台规范；拒绝后提示使用无附加元数据的 PNG/JPEG，不会静默剥离或重编码。白底/商品主体语义与人工边缘审核仍待 T02/D-02/D-04。
- 服务端生成不透明素材 ID 和存储 key，原始字节不重编码、不可覆盖；完整写入后事务登记资产和审计。DB 失败不产生可访问的资产记录，孤立对象留待 D-08；未完成 HTTP 上传不写对象。没有新增表/列需求，沿用 V1/V2，既有迁移不改。
- `GET /api/v1/assets/{id}` 返回上述安全元数据；`GET /api/v1/assets/{id}/content` 由 Java 鉴权代理原始字节（attachment/no-store/nosniff）。不返回 object_key、文件系统路径或长期外链。猜测跨项目素材、任务、产物以及重试均被拒绝；T05 Worker 权限/协议不变。

上传错误：未授权 401、无权项目/素材 404、非法类型/结构 400、体积/像素预算 413、MIME 不匹配/不支持 415、损坏或未支持元数据 422；响应不回显密码、请求体、文件路径或原文件名。生产本地账号、生产会话/存储/上传防护尚待独立实现与验收；未确认的项目成员与角色细节不在此次推定，已确认的删除权限见第 8 节。

## 9. T04-PROD：生产本地账号 API 子范围

PRD-G08 / ACC-14、ACC-09。独立 `prod-local` profile 组合 runtime/database，必须 `APP_ENV=production`、启用服务端 TLS；不能混入 dev-local 或其他 profile。不读取开发账号文件或静态用户 token。前端生产登录/管理页面不在此 API 子范围，既有开发页面不改为生产页面。

新增 V3：独立 `local_credentials`（user_id、唯一小写 username、PBKDF2 盐/摘要、ADMIN/USER）、`local_sessions`（仅 token SHA-256、user_id、到期时间）、`local_auth_throttle`（部署级登录窗口）。既有用户、原任务 Schema、V1/V2 不变，旧开发用户不会自动获得生产密码或管理员身份。生产角色仅授权账号管理；项目读取/素材/任务仍 owner-only，不隐含管理员跨项目读权。图片删除属于 T10。

首次启动空账号表需显式 `PROD_BOOTSTRAP_FILE`，仅含 username/salt/password_hash（无明文）；创建一个 ADMIN 和独立 users 记录。数据库事务锁保证多实例只初始化一次；已有生产账号后不再消费引导文件，不能借重启改密/恢复禁用用户。无默认账号、公开注册或初始化 HTTP 端点。工具生成随机盐，PBKDF2-HMAC-SHA256 600000 次、256 位摘要；新口令 6–15 字符（ADR-20260929-B；登录仍接受既有 ≤128 字符口令）、不截断，用户名 `[a-z0-9][a-z0-9_-]{0,63}`。管理员忘密且无其他可用管理员时须受控运维处理，不提供绕过认证的重置 API。

仅 prod-local 提供以下新路径，严格 JSON/未知字段拒绝；所有响应 no-store；错误不回显口令/摘要/token/请求体：

| 路径 | 输入与行为 |
| --- | --- |
| `POST /api/v1/local-auth/login` | `{username,password}` → 200 `{access_token,token_type:"Bearer",expires_at,user:{id,username,role},mode:"production-local"}`；错误/不存在/禁用统一 401 |
| `GET /api/v1/local-auth/me` | Bearer 或会话 Cookie → `{id,username,role,mode:"production-local",expires_at}` |
| `POST /api/v1/local-auth/logout` | Bearer 或会话 Cookie → 204，撤销当前会话，并清除 Cookie |
| `POST /api/v1/local-auth/password` | Bearer + `{current_password,new_password}` → 204；校验旧密码，撤销本人全部会话，重新登录 |
| `GET /api/v1/admin/accounts` | ADMIN，最多 100 项；返回 `{items:[{id,username,role,status}],next_after}`，可用 `after` 按 id 翻页，不返回密码或 token |
| `POST /api/v1/admin/accounts` | ADMIN + `{username,password,role:"USER"或"ADMIN"}` → 201 安全账号元数据；重名 409 |
| `POST /api/v1/admin/accounts/{id}/status` | ADMIN + `{status:"ACTIVE"或"DISABLED"}` → 204；禁用撤销全部会话；拒绝禁用最后一个 ACTIVE ADMIN（409） |
| `POST /api/v1/admin/accounts/{id}/password` | ADMIN + `{new_password}` → 204，撤销目标全部会话 |

会话为随机 256 位 opaque Bearer，数据库只存摘要；固定到期 `PROD_SESSION_SECONDS` 默认 28800（8 小时，ADR-20260929-C；原为 900），技术范围 60–86400 秒，重启保持有效，过期/退出/改密/禁用后失效。仅 Authorization 头，不用 URL 或 cookie。登录在数据库保存一个共享的 60 秒窗口，`PROD_LOGIN_LIMIT` 默认 60、技术范围 1–600；超出 429，重启不能清空。每用户最多 20 个有效会话，超出 429；登录时清理已过期会话。账号变更和安全审计同事务；账号操作重新验证当前 ADMIN，会话创建和改密/禁用通过行锁协调，避免旧口令竞争产生可用会话。

TLS 私钥/证书与 bootstrap 文件均外置且不入库；部署须使用受信证书，不信任客户端自行提供的转发头来替代 TLS。本轮实测可用临时自签名证书验证真实 HTTPS，不计生产证书或公网部署验收。

### 会话 Cookie（ADR-20260929-B）

登录成功（`/api/v1/local-auth/login` 与开发环境 `/api/v1/auth/login`）除响应体外还返回 `Set-Cookie: wb_session=<令牌>; HttpOnly; SameSite=Strict; Path=/api; Max-Age=<到期秒数>`，HTTPS 下带 `Secure`。请求没有 `Authorization` 头、路径以 `/api/` 开头、且浏览器标记 `Sec-Fetch-Site` 为 same-origin/none（或未标记）时，Java 把该 Cookie 视为 `Bearer` 令牌；`/internal/` Worker 接口从不读取 Cookie。退出时返回清除 Cookie 的 `Set-Cookie`。开发环境 `/api/v1/auth/me` 返回 `{id,username,mode,expires_at}`。页面不再保存或发送令牌，只以 `/me` 恢复登录状态。新设密码 6–15 字符。

v2 一个 task 表示一批，每个 attempt 依次执行 count 个独立背景调用和确定性合成。全部通过数量、实际格式/尺寸、来源及哈希检查后原子登记全部 COMPOSITE；任一失败则整个 attempt FAILED，零可见成功图，不展示或补齐部分结果。单图在批次提交前为未发布，批次完成后同时 SUCCEEDED；FAILED 批次内均不可见，不提供误导性逐图成功进度。显式重试整批重新执行并产生新 attempt；可能产生额外供应商费用，不自动重试不确定的付费调用。数量和参数冻结进幂等请求及 Worker v2 快照。

| `provider` | 必填字段（严格，不多不少） | 调用方式 |

## 16. v4 整图生成（ADR-20260929）

| 路径（`runtime` 各 profile，本人项目） | 输入与行为 |
| --- | --- |
| `POST /api/v4/generation-tasks` | 需 `Idempotency-Key`。按 `feature_type` 区分：GIFT 需 `gift_asset_id`、`gift_position`（`BOTTOM_RIGHT/BOTTOM_LEFT/RIGHT/LEFT`），可选 `background`（`SOLID/GRADIENT` 带颜色或 `CUSTOM` 带描述）与 `text`（页面自 ADR-20261008-G 起不再发送，接口为兼容保留）；SCENE 需 `scene_preset` 或 `scene_prompt`（可同时给出，描述追加在预设后）；SELLING_POINT 需带 `points` 的 `text`，以及 `style`（一个风格 id）或 `keep_original: true` 二选一，`output.count` 必须等于卖点条数（1–6，不受数量上限限制），每条卖点一张、每张为共用标题 + 该卖点（ADR-20261008-G；旧的 `styles` 数组写法 400）。都可带 `style_prompt` 与 `model_id`（§14c），`keep_original` 除外。`output` 为比例、宽高（64–2048、总像素 ≤ 4194304、与比例精确一致）、格式、数量（部署上限默认 4）。返回 202 任务 |
| `GET /api/v4/generation-tasks/{id}` | 任务状态与最终图（只列 COMPOSITE）、冻结的 `output`、提交时的 `request`、`bases`（本次模型原图 `{id,width,height}`，按序号；供页面在原图上预览改字，未成功时为空）、`review_status:"PENDING"`；重排任务另带 `source` |
| `POST /api/v4/generation-tasks/{id}/retypeset` | `{ordinal, text}`，需 `Idempotency-Key`。只对本人已成功的 v4 任务；用该张的模型原图重新叠字，**不调用模型、不绑定供应商、不占付费许可**；生成一个新的单张任务 |

- `text`：`title`（≤60 字，可含换行）与 `points`（≤6 条，每条 ≤20 字）至少一项；`color`、`size`（标题最大字号 12–240px）、`align`、`box`（相对画布的文字区）。程序按原文绘制，字号在框内自动缩小，最小 12px 仍放不下则 `TEXT_OVERFLOW`，绝不截断。
- 不需要抠图：商品原图（赠品入口另加赠品原图）按哈希冻结，作为参考图发给模型（OpenRouter `input_references`，base64 data URL；超过 1536px 或 4MB 的只为传输缩小副本）。适配器先核对模型声明支持图片输入与足够的 `input_references` 数量。
- 每张图：心跳 → 取得一次性付费许可 → 调用模型 → 本地 cover-center-v1 裁到精确尺寸 → 叠字 → 编码。模型原图作为 BACKGROUND 产物登记（供重排，不在任务结果中显示）；最终图为 COMPOSITE。回执逐张记录供应商、模型、提示词、参数、输入图哈希、变换与是否叠字；Java 核对尺寸、格式、哈希、裁切与输入哈希后原子发布，任一张失败则整批不发布。
- 赠品方框底色（ADR-20261008-J，纯白的实现由 ADR-20261009-N 取代）：`gift_card.background` 为 `ORIGINAL`（默认）或 `WHITE`。`WHITE` 时 Java 快照带 `gift_reshoot: true`，任务绑定出图模型（即使 `keep_original`）；Worker 在各张图片之前领取付费许可 `generation-calls/{count}`（序号 = `output.count`，只用于赠品重拍），把赠品原图作为唯一参考图、比例 1:1、模板版本 `generation-v4-gift-white`、关联 ID `<attempt>-gift` 调用一次模型，要求赠品单独放在纯白背景上且外形、颜色、Logo、文字、数量不变；同一任务各张共用这一结果。程序把返回图的近白背景校正为纯白、裁到赠品及其阴影、放大进方框、四周渐隐，不画描边；背景不够白时整张放入。回执 provenance 带 `gift_card {background, reshoot?, white_backdrop?}`，`reshoot` 为这次调用的来源记录（模型、提示词、关联 ID、输出哈希等，无密钥），Java 校验其 `output_source`、关联 ID 与哈希格式。带方框的任务重排返回 409 `TASK_CONFLICT`。
- 赠品方框与卖点商品位置（ADR-20261008-H）：GIFT 可带 `gift_card {size: S|M|L, label?: 1–10 字}`，Worker 用赠品原图绘制白色圆角卡片（顶部绿色“+”、文字在赠品下方），按 `gift_position` 贴到最终图（导出裁切之后、叠字之前，重排时同样重贴）；带方框时赠品不作为参考图发给模型，提示词要求该位置留空。方框 + `background.mode=ORIGINAL` 时快照带 `keep_original: true`，不绑定模型、不领取付费许可，底图为商品图居中裁切。SELLING_POINT 可带 `product_position: LEFT|CENTER|RIGHT`（不与 `keep_original` 同用），提示词改为把商品放在该侧。
- 卖点图（ADR-20261008-G）：Java 快照带 `per_point: true`；AI 风格时 `styles` 为所选的一个风格，Worker 第 i 张的提示词加入第 i 条卖点、叠字为标题 + 第 i 条卖点、配色取该风格。`keep_original: true` 时不绑定模型、不领取付费许可（`generation-calls` 返回 400），Worker 把商品图转正、透明处补白、按尺寸 cover-center-v1 裁切，作为每张的 BACKGROUND（各张相同，`output_source: original`，`source_transform` 记录从原图到该尺寸的裁切），再逐张叠字；Java 对此类回执不要求各张底图不同。重排时只用请求里的那段文字，不再按卖点拆分。旧任务（`styles` 数组、无 `per_point`）仍按每个风格一张、每张全部卖点处理。
- 错误：比例/尺寸/数量/风格数量/文字框越界 422 `INVALID_LAYOUT`；未知预设或风格 422；缺字体 `GENERATION_FAILED`（可重试，诊断 `TEXT_FONT_UNAVAILABLE`，在任何付费调用前失败）；文字放不下 `TEXT_OVERFLOW`（不可重试）；供应商失败 `PROVIDER_UNAVAILABLE`。
- Worker 配置：`GENERATION_TEXT_FONT` 指向支持中文的字体文件（部署用思源黑体/Noto Sans CJK，SIL OFL）；可选 `GENERATION_TEXT_FONT_INDEX`（字体集合 .ttc 中的字形序号，默认 0，Noto CJK 的简体中文为 2）；带文字的任务在任何付费调用前先实际加载一次字体，失败即 `TEXT_FONT_UNAVAILABLE`。可选 `OPENROUTER_PROXY_URL`（仅 http/https、无路径；只用于模型调用，环境里的 `HTTPS_PROXY` 等仍被忽略；格式错误按 `CONFIGURATION` 失败）。Java：`GENERATION_ENABLED`（默认 true）、`GENERATION_ASPECT_RATIOS`、`GENERATION_FORMATS`、`GENERATION_MAX_COUNT`（默认 4）。
