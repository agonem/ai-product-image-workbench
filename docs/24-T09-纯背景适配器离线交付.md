# T09-ADAPTER：纯背景接口与私有配置

需求 PRD-G11、PRD-S02；验收 ACC-16 / OR-1–6。2026-09-27。本次仅交付 Python 内部适配器，不接入 Worker 或宣称商品场景生成完整通过。

## 官方协议与兼容边界

本次核对 [OpenRouter 官方 Image Generation 文档](https://openrouter.ai/docs/guides/overview/multimodal/image-generation)：采用专用 `/api/v1/images`，先发现图片模型与每个 endpoint 的能力；按 provider tag 限定路由，关闭 fallback。请求只含文本及已核验的比例、resolution 档位、输出格式；响应接收 base64 图片，拒绝外链。模型级能力并集不替代 endpoint 能力。

不选择猜测的默认模型。仅支持 endpoint 明确提供 enum 描述的参数，其他描述保守拒绝。实际像素尺寸由供应商档位决定；本次不声称支持任意精确像素请求。实际输出比例必须精确一致，格式必须与 PNG/JPEG 请求匹配；不静默缩放或转码补救不符合请求的结果。

继续使用锁定的 Python 3.13、httpx 0.28.1、Pillow 12.3.0，无新增依赖。MockTransport、流式读取和 Pillow 内容校验已在现有锁文件环境运行。固定官方 HTTPS 地址，使用默认证书校验，禁止重定向，不继承宿主代理配置。16 MiB 响应、10 MiB 图片、16MP/4096 边长为当前技术保护预算，不是平台规范或业务数量上限。

## 配置与调用

`.env.example` 只提供注释占位，不自动载入。仅向 Python 服务进程注入 `OPENROUTER_MODEL`、`OPENROUTER_PROVIDER_TAG`，以及 `OPENROUTER_API_KEY` 或绝对路径 `OPENROUTER_API_KEY_FILE` 二选一。key 文件最多 4096 字节，放在仓库外私有目录并通过部署权限保护；不要传给前端或设置 VITE 前缀，不在命令行写真实 key。

在 image-service 目录运行配置语法检查（不联网、不验证凭据有效性）：

```bash
uv run --frozen python -m image_service.background_config
```

已取得配置后，服务端调用 `load_config()` → `OpenRouterAdapter(config)` 上下文 → `generate(BackgroundRequest(...))`。请求字段详见 docs/02 第 12 节；模型调用每次一张背景，调用者负责将业务数量编排为独立且可审计的请求，当前不实现该编排。`BackgroundResult` 返回字节、实际宽高、provenance；提示词/参数放私有来源记录，不写日志。使用 `with` 关闭客户端。其他官方/第三方/本地实现可实现 `BackgroundAdapter`，本次未实现或宣称它们真实接入。

默认 Worker 仍保持真实生成未开放。不得把单独适配器挂成面向前端的 Python API，也不得发送原商品图或赠品图。文本约束不能保证模型视觉内容，全部输出 `review_status:PENDING`。
