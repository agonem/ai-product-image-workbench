# T01 开发环境与版本选择

任务：T01｜需求：PRD-G06｜验收：ACC-T01｜核验日期：2026-09-24。

当前提供开发骨架。Java 管业务 API；Python 预留图像服务边界；浏览器仅访问 Java。尚无上传、图片生成、登录、数据库、队列或 AI 供应商配置。健康检查只说明 HTTP 进程能响应。

## 1. 运行前提与版本

安装 Node.js 24.15.0（npm 11.x）、JDK 21、Python 3.13 和 uv 0.12.5。首次安装需要访问 npm、Maven Central、PyPI。Maven 使用仓库内 Wrapper 自动下载 3.9.16，无需另装 Maven。

## 2. 首次安装与检查

以下命令都从仓库根目录执行，PowerShell、Git Bash、macOS/Linux 终端均可用；Windows 若 `npm` 被 PowerShell 策略拦截，使用 `npm.cmd`。

```text
npm --prefix frontend ci
uv sync --frozen --project image-service
python scripts/check.py
python scripts/smoke.py
```

`check.py` 依次检查前端格式/ESLint/HTTP 客户端测试/TypeScript/生产构建、Java 格式/编译/HTTP 测试/可执行 JAR、Python 锁文件/Ruff/pytest；任一失败返回非零。格式检查不自动修改文件。

`smoke.py` 在 18080、18001、15173 启动三服务，检查 Java、Python、前端代理、HTML 入口和未实现任务边界，完成或失败都会清理自己启动的进程。启动日志位于忽略的 `.artifacts/smoke/`。端口被占用会直接失败，不会终止其他进程；可设置 `SMOKE_BUSINESS_PORT` / `SMOKE_IMAGE_PORT` / `SMOKE_FRONTEND_PORT` 改端口。

## 3. 本地启动

先完成上节安装与构建，再打开三个终端，分别在仓库根目录运行：

```text
python scripts/dev.py business
python scripts/dev.py image
python scripts/dev.py frontend
```

- 工作台：[http://127.0.0.1:5173](http://127.0.0.1:5173)。应显示“业务服务已连接”，点击“重新检查连接”再次请求 Java。
- Java：[http://127.0.0.1:8080/api/v1/health](http://127.0.0.1:8080/api/v1/health)。返回 `service=business-service`。
- Python：[http://127.0.0.1:8001/internal/v1/health](http://127.0.0.1:8001/internal/v1/health)。返回 `service=image-service`；浏览器页面不会调用它。
- 各终端按 Ctrl+C 结束对应服务。前端支持热更新；Java 修改后须重新构建 JAR 并重启，Python 修改后须重启。

三个原生命令等价于：前端目录 `npm run dev`；业务目录 `java -jar target/business-service.jar`；图像目录 `uv run --frozen python -m image_service`。推荐使用 `dev.py`，它统一处理 Windows 进程清理及下述本机 JDK 兼容问题。

## 4. 环境配置

无任何密钥也能完成 T01。根 `.env.example` 仅列出 Java/Python 的进程环境变量；Java、Python 和脚本**不会自动加载** `.env`。需要覆盖时在启动终端设置变量，例如 PowerShell：

```powershell
$env:BUSINESS_PORT = "8082"
python scripts/dev.py business
```

Git Bash / macOS / Linux：

```bash
BUSINESS_PORT=8082 python scripts/dev.py business
```

前端如需更改代理，把 `frontend/.env.example` 复制为 `frontend/.env.local`，设置 `DEV_API_TARGET=http://127.0.0.1:8082` 并重启前端。Vite 使用 `DEV_HOST` / `DEV_PORT` / `DEV_API_TARGET`；这些值只用于开发服务器，不是产品配置。不要在前端环境文件中放密钥。

默认端口 5173 / 8080 / 8001 仅为内部开发默认值，与拼多多图片规则无关。全部默认绑定 `127.0.0.1`。尚无认证的骨架不可直接用于公网或生产。

Windows 本机出现过 JDK 选择器 `UnixDomainSockets.connect0: Invalid argument`。保持代码不变，仅为子进程设置 `jdk.net.unixdomain.tmpdir` 为项目 `.artifacts/java-tmp` 后可恢复。因此 `check.py`、`dev.py`、`smoke.py` 在 Windows 统一加入该进程级参数，不修改系统环境；如果调用者已设置该参数则保留。项目路径宜简短（Unix socket 路径有长度限制）。[OpenJDK 官方排障建议](https://mail.openjdk.org/pipermail/nio-dev/2023-March/013297.html)。底层操作系统原因尚未确认，已验证的是更换目录的效果。

## 5. 单独检查与格式修复

```text
npm --prefix frontend run check
uv run --frozen --project image-service ruff check image-service scripts
uv run --frozen --project image-service ruff format --check image-service scripts
uv run --frozen --project image-service pytest image-service/tests
```

Java 从 `business-service/` 执行 `./mvnw -B -ntp verify`（PowerShell 用 `./mvnw.cmd`；Git Bash 可用 `bash mvnw`）。在存在上述 JDK 问题的 Windows 环境，优先用根目录 `python scripts/check.py`。

需要主动修复格式时：

```text
npm --prefix frontend run format
uv run --frozen --project image-service ruff format image-service scripts
```

Java 在业务目录执行 `./mvnw spotless:apply`（Windows 用 `./mvnw.cmd`）。Ruff 的 `check --fix` 仅在希望自动修复可修正规则时使用，不放进 CI。

## 6. CI 与业务边界

`.github/workflows/ci.yml` 在 push、pull_request 或手动触发时，分别在 Ubuntu/Windows 安装锁定依赖，运行相同 `check.py` 与 `smoke.py`，失败时保留诊断日志。CI 无需真实密钥。当前交付的本机运行证据不能代替托管 CI 已通过的证据；需把项目提交到 GitHub 后实际触发。

P0 D-01..D-05 状态未变：分别阻塞平台正式规格、主体保真/人工审核、在线背景供应商、真实素材验收、正式认证隔离。T01 不依赖这些事项。T03 契约/数据库迁移可以按任务依赖继续；T02/T04/T09 涉及对应决定时再推进。未新增真实素材、平台尺寸常量、供应商或密钥。
