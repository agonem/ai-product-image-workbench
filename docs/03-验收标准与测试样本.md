## ACC-T03：任务契约与数据库迁移

对应 T03、PRD-G03/G06、PRD-S01/S02/S03；为 ACC-07/08/10 提供基础，不代表完整业务链路验收。

1. 三端对同一批正反 JSON 样本给出一致结果：三种独立输入、缺少功能专有字段、混入其他功能字段、未知字段、错误类型/版本、无效日期/哈希/对象 key、状态与产物/错误不一致。
2. Worker 请求保留原商品/alpha、赠品独立引用及人工文案；成功/失败回执必须指向具体 task 和 attempt；校验器离线解析 schema，错误输出不回显载荷内容。
3. 在真实 PostgreSQL 空库上实际执行 Flyway V1；重复启动迁移为零新增，校验通过；修改已应用迁移的校验和必须被拒绝。
4. 数据库验证同用户/功能/key 的重复及并发插入最多保留一个任务；不同 payload 不得越过唯一约束；不同用户/功能允许独立 key；Java 指纹测试验证对象键重排、数字表示与内容变化。
5. 验证 attempt 序号唯一、跨任务/跨项目外键、产物槽位唯一、outbox/回执唯一、状态及哈希约束、已发布版本和历史请求不可覆盖；SQL 失败需断言具体约束/SQLState，而非只观察任意异常。
6. 默认三服务仍能启动；Java database profile 对真实临时 PostgreSQL 能启动并迁移，缺失/错误数据库配置不能静默跳过。Python 不写业务库。
7. CI 配置包含独立数据库验证入口；未实际运行的托管/平台检查明确列出。无图片产物，真实图片保真/人工审图不适用；认证、Worker 执行、重试恢复、下载仍待后续任务。

## ACC-T05：任务运行时与恢复

1. 默认健康模式不开放任务入口；runtime 无令牌/非本机绑定拒绝启动；无权用户/Worker 不能交叉访问，素材读取限任务快照。
2. 同 key 同内容及并发提交只建一个 task/attempt/outbox；不同内容 409；事务异常不留下半个任务。
3. Java/Python 两个真实进程通过 HTTP 运行合成 fixture 成功链路；查询和受权内容代理可读结果，公开响应不泄露对象 key。
4. 重复 claim 不同 Worker 不同时取得同一租约；回执重复不增加产物，不同载荷冲突；旧租约/旧 attempt 回执不覆盖新状态，拒绝伪造/缺失/错哈希产物。
5. Java 重启后未投递 outbox 可消费；Worker 在领取后宕机、写对象后宕机、保存回执后宕机、回执提交后响应丢失均可恢复。租约耗尽失败可见；退避/上限生效；并发/重复手动重试只产生一次新 attempt。
6. V1 原文不变，V2 迁移在真实 PostgreSQL 验证；原请求/模板快照不变，重复/晚到不能覆盖已登记对象或产物。
7. 本地对象存储路径回退、符号链接、超预算/非图片、跨 attempt 写入均拒绝；错误消息不回显敏感载荷。Worker journal 不记录 Bearer 密钥。
8. 明确区分 fixture 的运输成功与实际商品图生成，默认未实现 pipeline 明确失败；不选择供应商或平台规格。实际命令、失败修复过程和未运行平台逐项报告。
