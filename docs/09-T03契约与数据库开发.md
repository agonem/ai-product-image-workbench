# T03：契约与数据库开发

需求 PRD-G03/G06、PRD-S01/S02/S03；验收 ACC-T03，提供 ACC-07/08/10 的基础约束。三端健康服务与 T01 启动方式保持可用。新增的是可调用的契约校验模块和真实数据库迁移，任务 HTTP 写入、消息发布/消费、登录和图像处理尚未实现。

## 校验器与使用范围

规范源是根目录 contracts/*.schema.json，公共定义在 common.schema.json。三端消费同一份文件：
- frontend/src/contracts/validate.ts：validateContract(name, value)。
- business-service/.../contract/ContractValidator.java：validate(name, JsonNode)。
- image-service/image_service/contracts.py：validate_contract(name, value)。

返回空列表表示结构有效，非空列表只含 Schema 路径与错误关键字，不回显字段值。未知契约直接报错。注册表只装载仓库/JAR 的七份 Schema，不下载输入提供的链接。Python 从仓库根目录读取，未来独立打包 image-service 时必须同时打包 contracts；当前支持仓库方式启动。

Java 的 RequestFingerprint.sha256(rawJson) 是 v1 唯一指纹计算方；拒绝重复键和尾随 JSON，排序对象键、规范数字、保留数组顺序和字符串原文。它是项目协议，不宣称 RFC 8785。调用顺序应为严格解析/契约及授权校验 → 计算指纹 → 事务写入；T05 再接入业务接口。不要把哈希当作授权证据。

## 安装与普通启动

在根目录执行：

```text
npm --prefix frontend ci
uv sync --frozen --project image-service
python scripts/check.py
python scripts/smoke.py
```

普通检查运行三端格式、静态/类型检查、单元及共享契约测试、构建。它明确提示数据库测试没有包含在内。smoke 启动三端并通过 HTTP 校验，完成后停止自身启动的进程。

开发时分别执行 python scripts/dev.py business、image、frontend。默认不启用数据库；健康页不是业务工作台，也不代表数据库就绪。

## 独立数据库验证（推荐）

准备 PostgreSQL 17 原生 bin，设置 PG_BIN 指向含 initdb、pg_ctl、postgres、psql 的目录，然后在根目录运行：

```text
python scripts/check_db.py
```

Windows 示例：

```powershell
$env:PG_BIN = 'D:/tools/postgresql/pgsql/bin'
python scripts/check_db.py
```

本机开发辅助下载位于忽略目录 .tools/postgresql-17.11/pgsql/bin；该路径是默认查找位置，二进制不提交仓库。下载 ZIP：postgresql-17.11-4-windows-x64-binaries.zip；本次 SHA-256 为 b9424ee7bc60b52450ff910a3630225df32e633f3cb29c1d126d9299d59aea28。另一台机器从上述官方入口安装，并明确设置 PG_BIN。

脚本为每次执行创建全新集群、随机端口与一次性随机口令，只监听 127.0.0.1，使用 SCRAM。不会读取 DB_URL 或复用已有数据库。通过 Java Maven Failsafe 执行迁移/约束测试，再启动 database profile、检查健康及迁移历史，并验证缺失配置启动失败。结束时停止集群；诊断与合成测试数据保留在 .artifacts/postgres/，口令文件删除。Linux 上以普通用户运行 initdb，不能使用 root。

底层测试命令为 business-service/mvnw -Pdatabase-tests verify（Windows 使用 mvnw.cmd），要求 DB_TEST_URL、DB_TEST_USER、DB_TEST_PASSWORD，且会在目标库创建随机 test_* schema；**仅允许指定隔离测试库**。变量缺失会失败，不会静默跳过。日常优先用 check_db.py，避免误连业务库。

CI 新增独立 PostgreSQL 17.11 服务任务，使用只供短期 CI 容器的固定测试口令和合成数据；没有生产凭据。常规 Windows/Ubuntu 检查仍独立运行。CI 的数据库任务执行 Maven 集成测试；本地 check_db.py 还覆盖启动与缺配置失败。

## 连接自建开发数据库

仅在准备好空的开发库和账号后，设置下列进程环境并运行 python scripts/dev.py business：
- SPRING_PROFILES_ACTIVE=database
- DB_URL=jdbc:postgresql://127.0.0.1:5432/workbench
- DB_USER=你配置的开发账号
- DB_PASSWORD=通过本地环境提供的口令

.env.example 是说明模板，不自动载入；不得提交真实口令。URL 不携带密码。首次启动应用 V1；后续启动校验迁移历史，不重复建表。迁移错误使启动失败。Flyway clean 禁用，不启用 baseline-on-migrate。

V1 创建 11 张业务表，含任务幂等唯一键、同任务/项目的复合外键、attempt/产物/outbox/回执唯一键、快照与发布版本保护触发器。没有用户/模板种子、SSO/RLS 规则，也没有默认 AI 供应商。users.role 保留可空文本，待 D-05。ACTIVE/DISABLED、PENDING/APPROVED/REJECTED 等仅为基础存储状态，不是权限或人工审核批准流程。

迁移一旦应用于共享环境，不编辑 V1；新增 V2。V1 的首次交付前测试调整只发生在一次性本地数据库。数据库只校验基础结构与关系，完整 Schema/权限/业务状态机仍必须由 Java 事务服务执行。没有自动回滚、自动清空或删除传播；备份/恢复和保留策略待 D-08/T10。
