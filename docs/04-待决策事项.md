状态：通过。决定人：用户。日期：2026-09-30。依据：用户反馈“业务账号上传商品图和赠品图提示‘只支持内容匹配的 PNG/JPEG 图片’”，并要求“上传图片不限制格式，不限制像素大小”。

- 原因（测试服务器访问日志核实）：服务端要求浏览器声明的文件类型与实际内容完全一致，并拒绝带 EXIF、色彩配置、文字等附加信息的 PNG/JPEG；同一张图在不同电脑、不同文件名下声明类型不同，于是时好时坏（日志中 415/422 与 201 交替出现），与账号无关。
- 决定：以文件内容判断类型，不再看浏览器声明；PNG/JPEG 原样保存（保留全部元数据，包括手机照片方向、CMYK、色彩配置）。其他浏览器能打开的格式（WebP、GIF 首帧、BMP、AVIF、ICO 等）由页面转为无损 PNG 后保存——保存的是像素内容相同的 PNG，不是原文件字节（对 AGENTS“原始上传文件保留”的明确例外）。HEIC、TIFF 等浏览器打不开的格式提示先另存为 JPG/PNG。
- 大小：取消业务上的像素限制，只保留防止服务器被拖垮的安全上限——单个文件 50MB、1 亿像素（`OBJECT_MAX_BYTES`、`OBJECT_MAX_PIXELS` 可调，技术上限 64MB / 4 亿像素）；nginx 上传上限 60MB。服务端只读文件头取尺寸，不整图解码；发给模型时 Worker 按 EXIF 方向转正、转 RGB、缩到 1536px。
- 影响：接口 §7 上传规则、验收 ACC-T04 A3、V4-A14、V4-B10。

### ADR-20261008-L 补充（同日）：魔法棒 404 与错误提示

- 现象：测试服务器两条开魔法棒的任务失败，页面只显示“生成服务未配置或暂不可用（PROVIDER_UNAVAILABLE）”。Worker 回执诊断为 `PROVIDER_HTTP_404`：文本模型 `deepseek/deepseek-v4.1-flash` 的路由标签填了 `openai`，而 OpenRouter 上该模型没有 OpenAI 这个服务商，请求被限定只用 OpenAI，因此 404。

## ADR-20261009-M：对话生图按页面名称告诉模型每张图是什么

状态：通过（修正）。决定人：执行方（修正用户报告的问题，不改变功能范围）。日期：2026-10-09。依据：用户截图与问题“为什么生成图片不符合要求？是因为不理解商品图、参考图1、参考图2 的含义吗？”。

- 现象（测试服务器任务 `c47dffee…`、`9a21795f…`、`bc71d56b…`）：用户写“在参考图1的基础上加商品图作为赠品，赠品的展示方式可以参考参考图2”，结果反过来——商品（洗头刷）成了主角，参考图1 里的浴巾被放进了方框；另两条也出现了角色错位或参考图整张被塞进方框。
- 原因（核对了实际发给模型的提示词）：
  1. 编号冲突：程序对模型说“Reference image 1 is the product… Reference image 2/3 is an extra reference”，而页面上叫“商品图 / 参考图 / 参考图2”，用户自然把第一张参考图叫“参考图1”。模型把“参考图1”对上了“Reference image 1”，也就是商品图。
  2. 默认把商品当主角：保护条款写“无论怎么改都保持 reference image 1 的商品”，智能体 Gloria 的设定又写“商品是绝对主角”，与“以参考图为底图、商品作赠品”的要求冲突。
  3. 参考图只被说成“用户给的额外参考”，用途全靠模型猜。
- 修正：
  - 提示词按页面名称逐张介绍：“input image 1 = 「商品图」(the product); input image 2 = 「参考图1」; input image 3 = 「参考图2」”，并明确“「参考图1」是第 2 张，不是第 1 张”；修改时第 1 张为「要修改的图」（用户也可能说“这张图”“当前图”）。
  - 写明每张图的用途由用户决定：参考图可以是底图、要加入的物品或只是风格/版式示例；商品可以是主角，也可以作为赠品加入。以某张图为底图时保留其人物、物品、文字、Logo 和版式，只做要求的改动。
  - 保护条款改为“商品图里的商品出现在哪里都保持原样”（不再暗示商品必须是主角）；参考图里被采用的物品也保持原样；已保留的图片里原有的文字不改，不新增文字。
  - 智能体设定与用户原话冲突时以用户为准；魔法棒改写时告诉文本模型图片名称，并要求沿用这些名称、按用户安排用途。
  - 页面：输入区第一张参考图改名“参考图1”；对话里每条消息下的小图标注“商品图 / 参考图1 / 参考图2”；有参考图或在修改时，输入框上方提示可直接用这些名称描述；清空参考图1 时参考图2 自动前移，保证名称与发送顺序一致。
- 不变：仍是同一次出图调用，不增加费用；结果待人工审核。效果需真实出图确认（未做新的付费调用）。
- 影响：docs/02 §20；docs/03 V4-A24、Worker 单元测试；无接口和数据库变化。

## ADR-20261009-N：赠品方框“纯白”改由 AI 重拍赠品（取代 ADR-20261008-J 的程序去底）

状态：通过。决定人：用户（改用 AI）；提示词与合成方式为执行方方案，可改。日期：2026-10-09。依据：用户反馈“使用不是纯白赠品图生成时，抠出的赠品边框阴影过深、不协调，能不能直接改用 AI 模型生成而不是使用程序抠出赠品？”。

- 现象（任务 `22dc3ea3…`、`396b68e8…`、`1ec2a2c2…`，赠品图为米粉色背景的硅胶洗头刷）：程序去底后给浅色赠品加的灰蓝描边偏深，加的投影偏重，赠品底部还残留一条原背景的米色阴影带。
- 做法：方框底色选“纯白”时，把赠品图单独发给所选出图模型，要求“只保留这件赠品、放在纯白背景上、外形/颜色/Logo/文字/数量不变、去掉原背景和背景上的文字与杂物、带自然浅阴影（浅色赠品也看得清）、不加任何文字和边框”，比例 1:1。程序再把模型返回的白底图：
  1. 按边缘取背景色，把接近白色的背景校正为纯白（赠品颜色按同一比例保持）；
  2. 裁到赠品和它的阴影所在范围，放大到方框图片区；
  3. 四周渐隐到方框的白色，不画描边，也不额外加投影。
  模型返回的背景明显不是白色时，原样整张放进方框（同“原图背景”的样子），回执记录 `white_backdrop: false`。
- 费用与次数：每个任务多 1 次出图调用（与张数无关，同一任务的几张图共用这一个赠品）。“保持原图背景 + 纯白方框”以前不调用模型，现在会调用 1 次（只重拍赠品，商品原图仍完全不变）；“原图背景”底色仍不调用模型。失败重试会重新调用一次。
- 保真：赠品作为参考图发给模型，符合 ADR-20260929；重拍的赠品可能有细微差别，结果待人工审核；回执记录这次调用的模型、提示词、关联 ID 和输出哈希（`gift_card.reshoot`）。
- 程序去底（ADR-20261008-J 的分离、描边、投影）已删除。
- 接口与数据：创建请求不变（`gift_card.background: WHITE`）；Worker 快照新增 `gift_reshoot: true`，此时即使 `keep_original` 也绑定出图模型；付费许可 `generation-calls/{count}`（序号 = 张数，排在各张图片之后）专用于赠品重拍；回执 `gift_card` 改为 `{background, reshoot?, white_backdrop?}`，Java 校验 `reshoot` 的来源、关联 ID（`<attempt>-gift`）与哈希；带赠品方框的任务不能“应用文字修改”（409，本来就没有文字）。无数据库迁移。
- 页面：纯白说明改为 AI 重拍及多 1 次调用的提示；输出设置在“保持原图 + 纯白”时显示模型选择和“只用所选模型把赠品重拍成白底（1 次）”；预览角标“纯白·生成时 AI 重拍”。
- 影响：docs/02 §16；docs/03 V4-A22、V4-B17；契约 generation-v4-request/completed；ADR-20261008-J 中“程序去底、浅色描边”作废。

## ADR-20261009-O：对话生图以某张图为底时不动原图内容；可选与豆包同系列的出图模型

状态：通过（修正提示词）；模型选择待用户决定。决定人：执行方（修正），用户（是否改用其他模型）。日期：2026-10-09。依据：用户反馈“为什么会移除原本图片里的内容加上赠品，而不是自动在其他位置生成而不影响原背景？怎么达到和豆包相同的效果？”（附豆包用同样图片和描述生成的结果：原图不变，左下角加白色圆角卡片 + 绿色“+” + 洗头刷 + 文字）。

- 现象（任务 `c0b4d7de…`，ADR-M 修正后）：三张图的角色已经正确（以浴巾图为底、洗头刷作赠品、按参考图2 的卡片样式），但模型删掉了原图的 KUB 标志、“瞬吸干爽 童趣萌款”标题和三个圆形角标，把卡片放在原标题的位置。
- 原因（推断，依据实际提示词和结果）：
  1. 出图模型 `gpt-image-2` 每次重新画整张图，不是只改局部；原图内容能否保留全靠提示词约束。
  2. 我们的保护条款写着“不要新增任何文字、字母、数字、水印、贴纸、角标或标志”，结果被删的正好是文字、标志和角标；同时提示词没有说明赠品该放在哪里、不能盖住什么。
  3. 豆包用的是字节自己的图像模型，并且允许模型画字（卡片里的“硅胶洗头刷”是模型画的），它的回复写明“在图 1 左下角添加”，说明它先选了空白位置。其内部做法外部看不到。
- 修正（提示词，不增加费用）：以某张图为底时，原图里每个人物、物品、文字、标志、角标、图标、版式、颜色和背景都保持原样、原位置，不删除、移动、缩放、遮挡、重画；新增的东西只放进底图的空白处（优先空着的下方角落），大小以放得下、不盖住人物、商品、文字、标志和角标为准；只作“展示方式”参考的图片只学展示方式，不搬它的人物、商品、文字和背景。“不画字”改为“不写新的文字、字母、数字和水印，新加的赠品卡片不带文字说明；这绝不意味着删除底图原有的文字、标志、角标”。
- 仍有差别：卡片里的文字（如“硅胶洗头刷”）在对话生图里不会由模型画出（D-13 未决定前保持不画字）。需要“原图像素级不变 + 带文字的赠品卡片”时，用“赠品主图”：背景选“保持原图”，打开赠品方框（纯白、填文字、位置选左下），效果与豆包截图一致，文字由程序按所选字体绘制。
- 可选模型（2026-10-09 查 OpenRouter 出图接口公开列表，未做真实调用）：`bytedance-seed/seedream-5-0-pro`（字节 Seedream 5.0，与豆包同一系列，路由标签 `seed`，每张约 0.045 美元，支持本系统全部比例，最多 14 张参考图）、`bytedance-seed/seedream-5-0-lite`（约 0.035 美元/张）、`google/gemini-3-pro-image`。管理员在“模型配置”新增即可，生成页模型下拉可选，不需要改代码。各模型效果需真实出图对比。
- 影响：docs/02 §20；Worker 单元测试；无接口和数据库变化。

### ADR-20261009-O 补充（同日）：照参考图的“展示方式”时不加装饰、保留“+”标

- 现象（任务 `9c5a50ca…`）：底图的标志、标题、角标已全部保留（上面的修正生效）；但赠品卡片变成半透明，左上角多了金色彩带蝴蝶结，参考图2 卡片顶部的绿色圆形“+”没有画出来。
- 原因（推断）：提示词只说“只学它的展示方式”，没说要照搬卡片的形状、颜色、圆标和符号；“不写新的文字、字母、数字”让模型把“+”也当成字去掉；“赠品”一词让模型按习惯加了礼品彩带，而提示词没有禁止自加装饰。豆包在回复里先把参考图的样式写成文字（白色圆角卡片 + 顶部绿色“+”标识 + 下方文字）再出图。
- 修正（提示词）：作为“展示方式”的参考图，要找出其中的展示形式并忠实复现：同样的边框或卡片、形状、颜色、透明度，以及上面每个圆标、图标、符号（如圆圈里的加号）和它们的位置，只把里面的物品换成用户的；不搬该图的人物、商品、文字和背景；用户没要求时不加参考图里没有的装饰（彩带、蝴蝶结、包装纸、吊牌、贴纸、闪光）。“不画字”改为“不写新的词、字母、数字和水印；从参考图照搬的简单符号（如圆标里的加号）可以画”。
- 仍是模型每次重画，结果有随机性；要求完全一致时用“赠品主图”的程序方框。可选的进一步做法（待决定，未实现）：魔法棒改写时让文本模型也“看图”，像豆包一样先把参考图的样式写成文字再出图。这需要能看图的文本模型，并且会把商品图和参考图发给该文本模型的服务商（目前文本模型只收文字，路由标签只是“优先使用”，看图时需改回固定服务商）。

## ADR-20261009-P：对话生图“先看图、写清样式、再出图”

状态：通过。决定人：用户。日期：2026-10-09。依据：用户问“现在的效果是先充分了解参考图里的细节，再结合商品图生成图片吗？”，并要求“在提示词里要求图片模型先看图、写清样式、再出图，这样默认就是相同效果”。

- 回答用户的问题：之前不是。提示词和图片是一次性交给出图模型的，模型直接出图，中间没有可见、可控的“先看懂再画”步骤。只在出图提示词里加一句“先看图、写清样式”也做不到：出图模型只返回图片，写不出文字说明，我们也无法确认它有没有照做。豆包的效果来自两步：先由能看图的语言模型把图片内容和样式写成文字（它的回复里能看到），再出图。
- 做法（默认开启）：管理员已配置文本模型时，对话生图每条消息在出图前先调用一次文本模型，并把所有输入图片（缩小到最长边 1024 的副本，按页面名称逐张标注）一起发给它。它按固定格式写一份说明（不超过 700 字）：
  - 【看图】底图里的人物、商品、文字、标志、角标、图标及位置，空白区域在哪、多大；“展示方式”参考图里卡片或边框的形状、颜色、透明度、圆角，圆标、图标、符号（如“+”）的颜色、形状、位置，以及卡片的大致大小和位置；商品图的外形、颜色、材质、Logo、包装文字和数量；
  - 【出图方案】以哪张图为底、加什么、放在哪个空白处、约占多大、用什么展示形式、哪些必须原样保留。
  - 规则与保护条款一致：沿用图片名称；按用户安排用途；不加用户和参考图都没有的装饰；不要求画新字（照搬的“+”等简单符号可以）；不改变商品。
- 出图：提示词在用户原话之后附上这份“看图分析与出图方案”，冲突时以用户原话为准；保护条款照常追加。点亮魔法棒时，看图分析和按智能体设定改写在同一次文本调用里完成（对话里显示“某某 看图改写”）；不点亮时显示“看图分析”。
- 未配置文本模型时不做看图分析，按原方式出图；输入区说明显示“未配置文本模型，不做看图分析”。
- 失败：看图分析失败时显示“看图分析失败：文本模型……”，不调用出图模型、不产生出图费用，可重试。
- 费用与时间：每条消息多一次文本调用。以现用的 `deepseek/deepseek-v4.1-flash`（输入 0.3 美元/百万 token，输出 1.2 美元/百万 token，支持图片输入）估算，约 0.002 美元/条；多等约 5–15 秒。效果和耗时以真实调用为准（未做真实调用）。
- 数据去向：商品图、参考图（及要修改的图）的缩小副本会发给管理员配置的文本模型服务商；该模型的路由标签只是“优先使用”（ADR-20261008-L 补充），OpenRouter 会交给提供该模型的服务商处理。建议把文本模型的路由标签改为实际要用的服务商（如 DeepSeek 官方 `deepseek`）。
- 接口与数据：创建请求不变；有文本模型时 CUSTOM 任务快照带 `analyze: true` 并绑定文本模型版本；回执 provenance 新增 `analysis {text, text_model}`；任务详情新增 `analysis {text?}`；Worker 诊断码前缀 `VISION_`。无数据库迁移。
- 影响：docs/02 §21；docs/03 V4-A25、V4-A26、V4-B19；docs/08；docs/10；契约 generation-v4-request/completed。

### ADR-20261009-N 补充（同日）：赠品方框的圆标和圆角边缘平滑

- 现象：用户反馈赠品页生成图里的绿色“+”圆标边缘不圆润、锯齿感强。
- 原因：圆标、白色“+”、卡片圆角和赠品照片的圆角都由程序（Pillow）在最终尺寸上直接绘制，Pillow 画圆和圆角不做边缘平滑；800×800 的图上圆标直径只有约 44 像素，台阶状边缘明显。另一个问题是程序贴方框时把半透明边缘的透明度乘了两次，边缘会发暗；此前边缘不平滑，看不出来，纯白方框里赠品图的渐隐边可能已有一圈很淡的灰边。
- 修正：这些形状改为按 4 倍尺寸绘制，再按面积平均缩小（边缘自然过渡）；“+”改为两条圆头直条，不再是团块状；贴方框和放入赠品图时按标准透明度合成，边缘不再发暗。方框大小、位置、颜色不变；不增加费用。

## ADR-20261009-Q：模型可编辑、可删除、可配参数；生成页可选清晰度

状态：通过。决定人：用户。日期：2026-10-09。依据：用户指令“在后台模型配置界面添加模型删除、模型编辑功能，模型编辑里可以配置模型参数等；在赠品页、场景页、卖点页、对话生图页添加可选生成图片清晰度”，以及四项选择：清晰度“两样都能选”（尺寸和画质）、档位“标准 / 高清”、参数“按模型支持的参数列下拉”、删除“彻底删除，已提交的任务使用新默认模型完成和重试；默认模型要先换掉才能删”、编辑“直接修改模型配置，已提交的任务使用修改后的模型”。

- 取代此前“任务冻结模型版本、换密钥新增一行并让旧任务沿用旧版本”的做法（ADR-20260929-C、V6 不可变触发器）：
  - **编辑**：名称、接口类型、模型标识、路由标签、接口地址、走代理、启用、密钥（留空不改）和模型参数都可直接改；用途（出图/文本）不能改。已提交还没完成的任务、以及失败后重试的任务，都按改后的设置执行。换密钥同样直接生效。
  - **删除**：彻底删除；默认模型不能删（409 `DEFAULT_MODEL`，先把别的模型设为默认）。被删模型名下排队中、生成中、失败待重试的任务改绑当前默认模型（没有可用默认时改绑第一个启用的同用途模型）；已完成任务的回执和图片不变，只是不再关联这个模型（看板“按模型”里显示为“未调用模型或已删除”）。
- **模型参数**：从内置清单 `contracts/model-parameters.json` 按模型标识匹配可调参数，管理员在下拉里选，可“不指定”。清单按 OpenRouter 2026-10-09 公布的出图接口能力整理，且只放本系统能处理的取值（最高 2K，不含 4K）；生成前 Worker 仍会让 OpenRouter 核对一次：
  - GPT Image 系列：画质档 自动/低/中/高（2.5 另有很高、最高）；
  - Seedream 5.0 Pro、4.x、Flash：分辨率 1K/2K；Seedream 5.0 Lite：2K；
  - Nano Banana 2 / Pro / 2.1：分辨率 1K/2K；Nano Banana 2 Lite 与 Gemini 2.5 Flash Image：无可调参数；
  - 文本模型：创意程度（温度）0.2/0.5/0.7/1.0。
  业务服务不能连外网，所以下拉选项来自这份清单，而不是在页面上实时读取 OpenRouter；清单里没有的模型没有可调参数，也不支持高清。
- **清晰度**（四个生成页；对话生图合成一个下拉；**已被 ADR-20261009-R 改为“尺寸 + 1K/2K”**）：
  - 尺寸：标准 = 原有尺寸；高清 = 同比例约 2 倍、长边不超过 2048（800×800→1600×1600，750×1000→1500×2000，1000×750→2000×1500，720×1280→1152×2048，1280×720→2048×1152，800×1200→1360×2040，1200×800→2040×1360），并让模型按 2K 出图。只有能按 2K 出图的模型可选（Seedream、Nano Banana 2/Pro/2.1）；`gpt-image-2` 在 OpenRouter 上不能指定分辨率，只能选标准。不调用模型的“保持原图”可选高清尺寸，直接放大商品原图，原图较小时会变模糊（页面有提示）。
  - 画质：标准 = 模型配置里的参数；高清 = GPT Image 画质“高”，Seedream / Nano Banana 分辨率 2K。不调用模型时不显示。
  - 费用：高清会增加费用（如 Seedream 5.0 Pro 2K 每张约 0.09 美元，标准 0.045；GPT Image 高画质比自动档贵），以真实账单为准。
  - 所选模型不支持时：页面按钮置灰；接口返回 422 `MODEL_SIZE_UNSUPPORTED` / `MODEL_QUALITY_UNSUPPORTED`。个人模板不保存清晰度。
- 接口与数据：迁移 V16（`provider_config_versions.parameters`；不可变触发器只保护 id、用途、创建人、创建时间；任务对模型的引用可改，删除模型时已完成任务置空）；`DELETE /api/v1/admin/provider-configs/{id}`；`POST …/{id}/settings` 可改全部可编辑字段；`…/{id}/key` 原地换密钥；模型列表与选项带 `parameters` / `quality_high` / `size_high`；v4 创建请求可带 `quality: "HIGH"`；领取任务时模型配置带 `parameters`。
- 影响：docs/02 §14c、§16；docs/03 V4-A12、V4-A27、V4-B6、V4-B16；docs/08；docs/10。

## ADR-20261009-R：素材分类、只显示本次结果、商品默认居中、清晰度改为 1K/2K

状态：通过。决定人：用户。日期：2026-10-09。依据：用户指令“把商品图、赠品图、参考图、作品图作为素材图的分类……从商品图点击从素材库选择默认打开商品图分类，但可以看到赠品图、参考图、我的作品……素材管理页增加素材图分类”“赠品页、场景页、卖点页不显示最近结果，只显示当前任务生成的结果图片”“都修改成商品默认居中显示”“清晰度使用 1k、2k 这种格式显示”“背景里的保持原图/纯色/描述、赠品方框里的不加/加方框重新调整”，以及提问“为什么要单独添加一个清晰度尺寸，不能直接采用尺寸如 800x800、清晰度 2k 这种吗？”。

- **素材分类**：素材分为商品图、赠品图、参考图（新增）和作品图（生成结果）。
  - 分类只用于整理，任何一类都能放进任一位置：商品图位置可以选赠品图或参考图，赠品图位置可以选商品图，依此类推（取代此前“商品位置只收商品图、赠品位置只收赠品图”的规则）。
  - 各位置的“从素材库选择”默认打开同名分类，同时可切换到其他分类和“我的作品”；选了别的分类时提示“××也可以用作××；选中后不改变它在素材库里的分类”。从“我的作品”选仍是复制一份作为该位置分类的新素材。上传的图归入该位置的分类；对话生图的参考图位置归入“参考图”（此前存为赠品图的旧参考图仍在赠品图里）。
  - 素材管理页有“商品图 / 赠品图 / 参考图 / 作品图”四个分类；作品图只能查看、下载、删除，入口另有“打开我的作品”。
- **只显示本次结果**：赠品、场景、卖点页下方不再列出最近结果，只显示当前任务（刚提交或从“我的作品”打开的那一个）的图片，标题为“本次结果”；没有当前任务时不显示这一栏，画布占满。历史结果在“我的作品”。
- **商品默认居中**：赠品页和场景页的构图预览把商品区放在画面中间，提示词要求“把商品放在画面中间”（赠品放在所选角落；保持原图不改动任何内容）；卖点页“商品位置”默认改为“居中”（仍可选自动、左侧、右侧）。卖点文字框默认在左上，居中的商品会有约三分之一落在文字框下方，页面会提示重叠（只是提示，不阻止生成），可把文字移到上方居中或改选其他商品位置。
- **清晰度**（回答用户的问题：可以，而且更清楚，已按此修改，取代 ADR-20261009-Q 的“清晰度·尺寸 / 清晰度·画质”）：
  - 尺寸：一个下拉直接列出所有尺寸，原有 7 个之后追加 7 个大尺寸（1600×1600、1500×2000、2000×1500、1152×2048、2048×1152、1360×2040、2040×1360，长边不超过 2048）。
  - 清晰度：1K / 2K，指模型出图的分辨率，按所选模型可用的显示（Seedream、Nano Banana 2/Pro/2.1 有 1K、2K；Seedream 5.0 Lite 只有 2K；GPT Image 只有 1K；清单外的模型不显示清晰度，按模型自己的设置）。默认取模型参数里设的分辨率，选了大尺寸且模型支持 2K 时自动切到 2K。
  - 两者独立：模型按 1K 出图、导出成 1600×1600 时会放大，页面提示“可能不够清晰”；不调用模型的“保持原图”没有清晰度，大尺寸直接放大原图。GPT Image 的画质档改在后台模型参数里设。
  - 接口：创建请求 `quality` 改为 `resolution: "1K" | "2K"`；所选模型不支持时 422 `MODEL_RESOLUTION_UNSUPPORTED`；不再因输出尺寸拒绝任务。`quality` 字段只在 2026-10-09 当天部署过、未被使用，直接替换。
- **按钮组调整**：赠品页“保持原图 / 纯色 / 描述”“不加 / 加方框”“方框大小”“方框底色”改为占满整行、等宽排列（此前外框占满一行而按钮挤在左边）。
- **清理弃用代码**：删除早期抠图/合成预研（T02-SYN、T02-REAL，ADR-20260929 已取消抠图）留下的 `image_service/poc.py`、`poc_demo.py`、`real_review.py`、`review_render.py` 及其测试；生成流程用到的尺寸上限检查移入 `generation.py`。其余旧代码为历史数据与兼容保留（见 docs/08 §5）。
- 接口与数据：迁移 V17（`assets.kind` 增加 `REFERENCE`；任务的商品/赠品位置接受任一原图类别，仍拒绝抠图遮罩 ALPHA）；上传与“作品复制为素材”接受 `REFERENCE`；模型选项 `resolutions` / `resolution`；契约 generation-v4-create/request 的 `resolution`。
- 影响：docs/02 §22；docs/03 V4-A27、V4-A28、V4-B6、V4-B8、V4-B16、V4-B20；docs/06；docs/08；docs/10。

## ADR-20261010-S：画布（分三期；第一期为自动排列的画布）

状态：第一期通过并实现；第二、三期已定方向，开始前补契约。决定人：用户。日期：2026-10-10。依据：用户指令“赠品/场景/卖点页只实现所有结果按生成先后自动排在一块大画布上。拖动平移，滚轮缩放，双击放大预览，一键显示全部。对话生图页实现三档功能”；选择题回答“画布位置：右侧整块变画布”“画布文字字体：服务器上的商用字体”“第二期的删除：只从画布移除”“分三期，每期验收”；以及补充“这一点修改，依旧只显示本次结果”（ADR-20261009-R 不变）。

- **分期**：
  - 第一期（本次）：四个生成页都有画布。图片按生成先后自动排列；拖动平移（从图片上开始拖也可以）、滚轮缩放（以鼠标位置为中心，触控板双指捏合同样）、双击图片全屏预览、“显示全部”一键缩放到能看到全部内容；右下角另有缩小、放大和缩放比例（点比例回到 100%）。手机上单指拖动、双指缩放。画布获得焦点时方向键平移，`+` / `-` 缩放，`0` 显示全部。
  - 第二期（只在对话生图）：手动摆放、框选、从画布移除（不删除结果；永久删除仍只在“我的作品”）、复制、一键整理，位置保存。需要新数据表和接口，开始前先更新 docs/02。
  - 第三期（只在对话生图）：画布上加文字、加图片，拼成一张图导出；由 Python 合成（项目分工），不调用模型。文字用服务器上的商用字体（ADR-20261008-K，方正兰亭圆简体_中粗），浏览器里也要显示同一字体才能所见即所得，**开始前须由用户确认该字体授权允许网页嵌入使用**；不允许时再定替代方案。
- **赠品 / 场景 / 卖点页**：
  - 右侧整块是画布。左边是“编辑区”（原来的构图预览 / 生成结果：卖点文字框照常拖动缩放，对照原图滑块照常使用），右边是“本次结果”（仍只显示当前任务，ADR-20261009-R 不变；没有当前任务时画布上只有编辑区）。生成中的任务按要生成的张数显示占位。
  - 编辑区的工具（构图预览 / 生成结果、撤销 / 重做、文字框、图层、对照原图、尺寸）浮在画布顶部，不随缩放变小；“应用文字修改”浮在左下。原来编辑区自带的“适应画布 / 125% / 150%”由画布缩放取代。
  - 单击一张结果在编辑区打开（同原来），双击全屏预览；结果上的“放大查看 / 对照原图 / 下载 / 删除 / 重试”按钮不随缩放变小。
  - 打开页面、提交任务、结果出来、编辑区尺寸改变、窗口大小改变（用户没动过画布时）都会自动“显示全部”。
- **对话生图页**：
  - 布局改为三栏：对话列表 | 对话（消息与输入区）| 画布。窗口宽度不超过 1280px 时对话列表在对话上方、画布占右栏；手机上依次排列，画布在最后。
  - 画布显示当前对话的所有图片：每条消息一行，从上到下按发送先后，行首是“第 N 条”和这条消息的描述；生成中显示占位，失败显示原因和“重试”。
  - 单击图片选中并显示“继续修改 / 放大查看 / 下载”；双击全屏预览；下一条消息要修改的那张标“修改这张”。
  - 打开对话、发出新消息、结果出来时自动定位到最新一行；“显示全部”看整段对话。消息里的缩略图保留。
- **不加缩略图**：三页只显示本次结果、对话页只显示当前对话，图片数量有限；画布只下载屏幕附近的图片，下载过的不再重复下载。对话很长（上百张图）时缩小看全部会慢，到时再加缩略图（需要 Python 生成，另议）。
- 不改接口和数据库，不新增依赖（浏览器原生指针事件与 CSS 变换）。
- 影响：docs/03 V4-B14、新增 V4-B21；docs/06 §画布；docs/08 §4q；docs/10 §5.1、§5.5。

- **素材不预先选择**：赠品、场景、卖点页打开时商品图、赠品图都是空的（此前自动选中素材库里第一张），选择或上传后才显示；未选商品图时生成按钮上方提示“请先选择或上传商品图”。对话生图新对话同样为空；打开已有对话时沿用这段对话最后一条的商品图（不变）。
- 用户提问（待决定）：“使用 AI 模型生成图片后，还可以实现上传素材后，在右侧画布实时预览吗？”
  - 现状：生成前编辑区只在“保持原图”和赠品方框时显示真实素材，其他情况只有“商品 / 赠品”虚线框（2026-09-30 规范“不做合成预览”：模型会重画整张图，拼贴预览容易让人以为结果就是这样）；生成后编辑区停在结果上，换素材后要手动点“构图预览”。
  - 可选：A. 换素材后编辑区自动回到“构图预览”，并把素材照片放进虚线框作摆放示意（标注“示意，不是生成效果”），零费用、即时；B. 在画布上编辑区旁边列出本次选用的素材原图，零费用；C. AI 效果预览：每换一次素材调用一次模型（约 0.02–0.06 美元、20–40 秒），做不到实时，只能“换素材后点一次预览”，本质就是再生成一次。
  - 建议 A（可加 B）。**用户决定（2026-10-10）：“那就不用动，保持现在的情况”——不做，构图预览仍只显示虚线占位（保持原图与赠品方框除外）。**
- 不改接口、数据库和 Worker。
- 影响：docs/03 V4-B1、V4-B2、V4-B19、V4-B21；docs/06；docs/08 §4q；docs/10 §4b、§5.1、§5.5。

## ADR-20261010-V：画布第二期——对话生图的画布可以整理并保存

状态：通过。决定人：用户。日期：2026-10-10。依据：用户指令“对话生图页实现三档功能”“继续实现第二档”，以及 ADR-20261010-S 选择题回答“第二期的删除：只从画布移除”。范围以 ADR-20261010-S 第二期为准，只在对话生图页。

- **工具**：画布左下角工具条“选择（V）/ 抓手（H）”，默认“选择”。按住空格、按住鼠标中键或选“抓手”时拖动是平移；滚轮缩放、双击全屏预览、“显示全部”同第一期。手机上单指按在图片上是移动图片、按在空白处是平移，双指缩放。
- **选中**：单击图片选中；按住 Shift 或 Ctrl 单击加选 / 取消；在空白处拖出方框框选；Ctrl+A 全选；Esc 或单击空白处取消。只选中一张图时显示“继续修改 / 放大查看 / 下载”。
- **移动**：拖动选中的图片（未选中的图片拖动时先选中它）；方向键每次移动 10px（按住 Shift 50px），没有选中时方向键平移画布。
- **复制**：工具条“复制”或 Ctrl+D（也可 Ctrl+C 再 Ctrl+V），在右下错开 24px 放一张同样的图（同一张生成结果，不产生新文件、不调用模型），标“副本”。
- **从画布移除**：工具条“移除”或 Delete / Backspace。只是不在画布上显示，图片仍在“我的作品”和任务记录里；工具条“放回已移除（N）”把移除过的全部放回（排在最下方）。永久删除仍只能在“我的作品”。
- **一键整理**：按消息先后重新排成每条一行（副本排在原图后面），移除的保持移除。
- **撤销 / 重做**：工具条按钮，画布获得焦点时 Ctrl+Z / Ctrl+Shift+Z（或 Ctrl+Y）；只记录画布上的摆放、复制、移除、整理、放回，每个对话最多 50 步，刷新页面后清空。
- **说明文字**：不再有整行标题；每张图上方一行小字“第 N 条 · 图 M”（副本加“副本”），每条消息第一张图的说明还带描述（截断）、未完成时的状态和“详情”。生成中、失败的占位也可以移动和移除。
- **保存**：每次改动后约 0.6 秒自动保存到服务器（按对话保存，换电脑或浏览器打开相同）；从没整理过的对话按第一期的自动排列显示，第一次改动时才保存。新消息的结果自动排在现有内容最下方新的一行，并一起保存。另一个窗口改过同一对话的画布时，保存会被拒绝，页面载入最新摆放并提示。
- **不做**：改变图片大小、旋转、图层顺序调整、加文字、加图片、导出拼图（第三期）；赠品 / 场景 / 卖点页的画布保持第一期。
- 接口与数据：迁移 V18 新表 `conversation_canvases`；`GET / PUT /api/v1/conversations/{id}/canvas`；契约 `contracts/canvas-layout.schema.json`。见 docs/02 §23。
- 影响：docs/02 §23；docs/03 V4-A29、V4-B22；docs/06；docs/08；docs/10 §5.5。

## ADR-20261010-W：画布第三期——对话画布加文字、加图片、画板拼图导出

状态：通过。决定人：用户。日期：2026-10-10。依据：用户“验收通过”（第一、二期，ADR-20261010-S、V）、提问“在网页上不使用方正兰亭圆简体_中粗字体有什么影响？”后选择“使用 A”：编辑时网页用电脑自带字体近似显示，导出时由服务器用方正兰亭圆简体_中粗绘制，放不下自动等比缩小；字体文件不进网页（不涉及网页嵌入授权）。以下未由用户逐项指定的细节为本 ADR 的默认值，可以再调整。

- **范围**：只在对话生图的画布；赠品 / 场景 / 卖点页不变。
- **添加**（工具条“添加”菜单）：
  - **文字**：在画布中间加一个文字框（默认“双击编辑文字”、字号 48、深灰 #1D2129、左对齐，框 360 × 120）。只选中一个文字框时画布顶部出现文字设置：内容（最多 200 字、10 行，回车换行，不自动折行）、字号（24–160）、颜色（深灰、白、深棕、深蓝、橙红、主题蓝）、对齐（左 / 中 / 右）；双击文字框直接编辑内容。画布上用电脑自带字体近似显示，并按导出规则在框内等比缩小；设置区注明“画布上为近似显示，导出时用方正兰亭圆简体_中粗，放不下会自动缩小”。
  - **图片**：从素材库选择或上传（同其他页面的素材选择，作品图会复制为素材），按原比例放在画布中间。
  - **画板**：选一个尺寸（与生成页相同的 14 个尺寸），在画布中间放一个白色画板（长边 600），标题“画板 · 800 × 800”与“导出图片”按钮。只选中一个画板时可改背景色（纯白与 5 种浅色，同赠品页纯色背景）。画板总在其他内容下面。
- **调整**：只选中一个元素时右下角出现缩放手柄：图片、生成结果和画板保持比例，文字框可自由改宽高；工具条“置顶 / 置底”调整前后顺序（画板不参与）。移动、框选、复制、移除、撤销 / 重做、自动保存同第二期；文字、图片、画板“移除”就是删掉它（它们本来不是生成结果）。复制文字框、画板与图片同生成结果。
- **导出**：画板上点“导出图片”，把与画板重叠的所有图片、生成结果和文字按前后顺序拼成一张该尺寸的 PNG（超出画板的部分裁掉）。
  - 由服务器的 Python 合成，**不调用模型、不产生费用**，几秒完成。生成中在画板右侧显示占位，完成后结果出现在画板右侧，说明为“导出 · 800 × 800”；也出现在“我的作品”和任务记录，功能名“画布导出”，可下载、可“继续修改”（交给 AI 再改）。
  - 文字用方正兰亭圆简体_中粗（与卖点图相同的绘制规则：按换行分行、不自动折行，从所设字号起整体等比缩小直到放进文字框；小于 12px 仍放不下则这次导出失败，提示“文字放不下”）。页面在导出前用近似显示检查，放不下时提示并且不导出。
  - 画板里没有任何内容时“导出图片”不可用。
  - 导出用到的原图或结果在导出完成前被删除，导出失败并提示；重试同其他任务。
- **编号**：对话列表的“N 条”和画布说明“第 N 条”只计对话消息，导出单独计“导出”。新消息出图后自动成为“修改这张”的仍只看对话消息（导出结果要“继续修改”需手动选）。
- **不做**：旋转、描边阴影等文字效果、其他字体、多个画板一次导出、画板背景图片（可放一张图片铺满画板代替）。
- 接口与数据：迁移 V19（任务类型 `COMPOSE`，导出任务没有商品图）；`POST /api/v4/generation-tasks` 增加 `feature_type: "COMPOSE"`；`canvas-layout` 契约增加素材图、文字、画板三种元素。见 docs/02 §24。
- 影响：docs/02 §24；docs/03 V4-A30、V4-B23；docs/06；docs/08；docs/10 §5.5。
