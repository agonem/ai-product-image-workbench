状态：通过。决定人：用户。日期：2026-09-30。依据：用户反馈“业务账号上传商品图和赠品图提示‘只支持内容匹配的 PNG/JPEG 图片’”，并要求“上传图片不限制格式，不限制像素大小”。

- 原因（测试服务器访问日志核实）：服务端要求浏览器声明的文件类型与实际内容完全一致，并拒绝带 EXIF、色彩配置、文字等附加信息的 PNG/JPEG；同一张图在不同电脑、不同文件名下声明类型不同，于是时好时坏（日志中 415/422 与 201 交替出现），与账号无关。
- 决定：以文件内容判断类型，不再看浏览器声明；PNG/JPEG 原样保存（保留全部元数据，包括手机照片方向、CMYK、色彩配置）。其他浏览器能打开的格式（WebP、GIF 首帧、BMP、AVIF、ICO 等）由页面转为无损 PNG 后保存——保存的是像素内容相同的 PNG，不是原文件字节（对 AGENTS“原始上传文件保留”的明确例外）。HEIC、TIFF 等浏览器打不开的格式提示先另存为 JPG/PNG。
- 大小：取消业务上的像素限制，只保留防止服务器被拖垮的安全上限——单个文件 50MB、1 亿像素（`OBJECT_MAX_BYTES`、`OBJECT_MAX_PIXELS` 可调，技术上限 64MB / 4 亿像素）；nginx 上传上限 60MB。服务端只读文件头取尺寸，不整图解码；发给模型时 Worker 按 EXIF 方向转正、转 RGB、缩到 1536px。
- 影响：接口 §7 上传规则、验收 ACC-T04 A3、V4-A14、V4-B10。

- 实现：部署配置 `TEXT_FONT_FILE`、`TEXT_FONT_INDEX`、`TEXT_FAUX_BOLD`（中粗字体设为 false，不再额外描边加粗）；`check.sh` 改为检查所配字体能画中文并显示字体名。页面预览优先使用电脑上已安装的同名字体，未安装时用系统黑体近似，以生成结果为准。

## ADR-20261008-L：对话生图的智能体与“魔法棒”改写

状态：通过。决定人：用户。日期：2026-10-08。依据：用户参考“椒图 AI”的设计师选择（截图），指令“在对话生图页加入 agents，并且可以自定义 agents”，两项选择（先用 AI 改写需求再出图；公共 + 个人），以及补充指令“添加魔法棒图标，点击后由 AI 改写需求再出图，不点击直接使用 agents 配合需求出图”。

- 智能体：名称（1–20 字）、一句话介绍（≤60 字）、设定（1–2000 字，人设、擅长、出图偏好）、可选头像（上传图片，否则显示名字首字）。公共智能体由管理员维护，所有人可用，预置 3 个；个人智能体只有本人可见可改。对话输入区左下角为智能体选择（参考截图的列表样式），可选“不使用智能体”。
- 魔法棒（开关，在智能体旁）：
  - 关闭（默认）：不额外调用模型，把所选智能体的设定和用户描述一起交给出图模型。
  - 打开：先由文本模型按所选智能体（未选时为默认电商设计师）把描述改写成专业出图描述（中文，≤300 字，只描述画面，不要求画字，不改变商品），对话里显示“某某 改写：……”，再用改写结果出图。每条消息一次文本调用，与出图同属一个任务，可重试。
- 文本模型：管理员在“模型配置”里新增模型时选择用途“文本（智能体改写）”，与出图模型分开设默认；未配置文本模型时魔法棒不可用并提示。出图页面的模型下拉只列出图模型。
- 保护条款不变：无论是否改写，发给出图模型的提示词仍追加“保持商品外形、颜色、Logo、包装文字和数量不变，不在图里生成文字”。改写结果记录在回执，结果待人工审核。
- 接口与数据：迁移 V14：`agents` 表（`owner_id` 为空即公共）、`provider_config_versions.purpose`（IMAGE / TEXT）、`generation_tasks.text_config_version`；`GET/POST /api/v1/agents`、`PUT/DELETE /api/v1/agents/{id}`、`PUT/GET /api/v1/agents/{id}/avatar`；CUSTOM 任务新增 `agent_id`、`rewrite`；任务详情新增 `agent {id,name,rewritten?}`。

### ADR-20261008-L 补充（同日）：魔法棒 404 与错误提示

- 现象：测试服务器两条开魔法棒的任务失败，页面只显示“生成服务未配置或暂不可用（PROVIDER_UNAVAILABLE）”。Worker 回执诊断为 `PROVIDER_HTTP_404`：文本模型 `deepseek/deepseek-v4.1-flash` 的路由标签填了 `openai`，而 OpenRouter 上该模型没有 OpenAI 这个服务商，请求被限定只用 OpenAI，因此 404。
- 处理：文本模型的路由标签改为“优先使用”（该服务商不提供时自动换其他服务商），也可留空由 OpenRouter 选择（迁移 V15 放开约束；只发送文字描述，不含图片）。出图模型仍必须指定并只用该服务商。
- 错误提示：Worker 的诊断码（只含代码，不含服务商原文）会转成具体说明，如“魔法棒改写失败：文本模型不存在或路由标签不匹配（HTTP 404），请检查模型标识和路由标签”“出图模型的 API Key 无效或无权限（401）”；改写失败时不会发起出图付费调用。


## ADR-20261009-M：对话生图按页面名称告诉模型每张图是什么

状态：通过（修正）。决定人：执行方（修正用户报告的问题，不改变功能范围）。日期：2026-10-09。依据：用户截图与问题“为什么生成图片不符合要求？是因为不理解商品图、参考图1、参考图2 的含义吗？”。

- 现象（测试服务器任务 `c47dffee…`、`9a21795f…`、`bc71d56b…`）：用户写“在参考图1的基础上加商品图作为赠品，赠品的展示方式可以参考参考图2”，结果反过来——商品（洗头刷）成了主角，参考图1 里的浴巾被放进了方框；另两条也出现了角色错位或参考图整张被塞进方框。
- 原因（核对了实际发给模型的提示词）：
  1. 编号冲突：程序对模型说“Reference image 1 is the product… Reference image 2/3 is an extra reference”，而页面上叫“商品图 / 参考图 / 参考图2”，用户自然把第一张参考图叫“参考图1”。模型把“参考图1”对上了“Reference image 1”，也就是商品图。
  2. 默认把商品当主角：保护条款写“无论怎么改都保持 reference image 1 的商品”，智能体 Gloria 的设定又写“商品是绝对主角”，与“以参考图为底图、商品作赠品”的要求冲突。
  3. 参考图只被说成“用户给的额外参考”，用途全靠模型猜。
- 修正：
  - 提示词按页面名称逐张介绍：“input image 1 = 「商品图」(the product); input image 2 = 「参考图1」; input image 3 = 「参考图2」”，并明确“「参考图1」是第 2 张，不是第 1 张”；修改时第 1 张为「要修改的图」（用户也可能说“这张图”“当前图”）。
  - 写明每张图的用途由用户决定：参考图可以是底图、要加入的物品或只是风格/版式示例；商品可以是主角，也可以作为赠品加入。以某张图为底图时保留其人物、物品、文字、Logo 和版式，只做要求的改动。
  - 保护条款改为“商品图里的商品出现在哪里都保持原样”（不再暗示商品必须是主角）；参考图里被采用的物品也保持原样；已保留的图片里原有的文字不改，不新增文字。
  - 智能体设定与用户原话冲突时以用户为准；魔法棒改写时告诉文本模型图片名称，并要求沿用这些名称、按用户安排用途。
  - 页面：输入区第一张参考图改名“参考图1”；对话里每条消息下的小图标注“商品图 / 参考图1 / 参考图2”；有参考图或在修改时，输入框上方提示可直接用这些名称描述；清空参考图1 时参考图2 自动前移，保证名称与发送顺序一致。
- 不变：仍是同一次出图调用，不增加费用；结果待人工审核。效果需真实出图确认（未做新的付费调用）。
- 影响：docs/02 §20；docs/03 V4-A24、Worker 单元测试；无接口和数据库变化。

## ADR-20261009-N：赠品方框“纯白”改由 AI 重拍赠品（取代 ADR-20261008-J 的程序去底）

状态：通过。决定人：用户（改用 AI）；提示词与合成方式为执行方方案，可改。日期：2026-10-09。依据：用户反馈“使用不是纯白赠品图生成时，抠出的赠品边框阴影过深、不协调，能不能直接改用 AI 模型生成而不是使用程序抠出赠品？”。

- 现象（任务 `22dc3ea3…`、`396b68e8…`、`1ec2a2c2…`，赠品图为米粉色背景的硅胶洗头刷）：程序去底后给浅色赠品加的灰蓝描边偏深，加的投影偏重，赠品底部还残留一条原背景的米色阴影带。
- 做法：方框底色选“纯白”时，把赠品图单独发给所选出图模型，要求“只保留这件赠品、放在纯白背景上、外形/颜色/Logo/文字/数量不变、去掉原背景和背景上的文字与杂物、带自然浅阴影（浅色赠品也看得清）、不加任何文字和边框”，比例 1:1。程序再把模型返回的白底图：
  1. 按边缘取背景色，把接近白色的背景校正为纯白（赠品颜色按同一比例保持）；
  2. 裁到赠品和它的阴影所在范围，放大到方框图片区；
  3. 四周渐隐到方框的白色，不画描边，也不额外加投影。
  模型返回的背景明显不是白色时，原样整张放进方框（同“原图背景”的样子），回执记录 `white_backdrop: false`。
- 费用与次数：每个任务多 1 次出图调用（与张数无关，同一任务的几张图共用这一个赠品）。“保持原图背景 + 纯白方框”以前不调用模型，现在会调用 1 次（只重拍赠品，商品原图仍完全不变）；“原图背景”底色仍不调用模型。失败重试会重新调用一次。
- 保真：赠品作为参考图发给模型，符合 ADR-20260929；重拍的赠品可能有细微差别，结果待人工审核；回执记录这次调用的模型、提示词、关联 ID 和输出哈希（`gift_card.reshoot`）。
- 程序去底（ADR-20261008-J 的分离、描边、投影）已删除。
- 接口与数据：创建请求不变（`gift_card.background: WHITE`）；Worker 快照新增 `gift_reshoot: true`，此时即使 `keep_original` 也绑定出图模型；付费许可 `generation-calls/{count}`（序号 = 张数，排在各张图片之后）专用于赠品重拍；回执 `gift_card` 改为 `{background, reshoot?, white_backdrop?}`，Java 校验 `reshoot` 的来源、关联 ID（`<attempt>-gift`）与哈希；带赠品方框的任务不能“应用文字修改”（409，本来就没有文字）。无数据库迁移。
- 页面：纯白说明改为 AI 重拍及多 1 次调用的提示；输出设置在“保持原图 + 纯白”时显示模型选择和“只用所选模型把赠品重拍成白底（1 次）”；预览角标“纯白·生成时 AI 重拍”。
- 影响：docs/02 §16；docs/03 V4-A22、V4-B17；契约 generation-v4-request/completed；ADR-20261008-J 中“程序去底、浅色描边”作废。
